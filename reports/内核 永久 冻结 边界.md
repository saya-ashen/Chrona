# 先收缩公开义务，再永久冻结内核

**结论：不要冻结当前 API；先完成消费者迁移和安全一致性修正，再冻结最小治理契约。** “冻结后只能增加、永不删除”约束的是全部公开义务，而非工具名称数量：参数、返回值、错误、事件、Manifest、SDK 行为及身份含义都在其中。Chrona 的目标只保留**内核与模块**两类实体；Web、Notify 应是普通预装、可移除、可替换的模块，Agent 是唯一可信 builtin，Pi 是唯一内置 Provider。内核应永久承担真实身份、路由准入、受检生命周期、精确 owner 授权、共享资源治理、实际停止证据及必要的有限事实；创作、分发、日历、通知、配置和呈现归模块。当前 **60 个内核工具、21 个 Agent 工具及 9 个宿主私有方法**不能一起成为永久内核公共 API。本报告给出冻结候选、全部现有工具去向、冻结阻塞及迁移验收顺序；它不确定新工具总数，也不建议用一个 `execute/manage` 包装器掩盖原有义务。

**研究基线与证据。** 日期为 **2026-11-08**，仓库 `/home/saya/workspace/Chrona`，HEAD 为 `cf19ceb704800e5c53e0784aff4558883f6afa9b`。四份完整静态审计是本报告依据：[生命周期](../research_notes/内核%20永久%20冻结%20边界/module-lifecycle.md)、[系统治理](../research_notes/内核%20永久%20冻结%20边界/system-governance.md)、[协议与宿主](../research_notes/内核%20永久%20冻结%20边界/protocol-sdk-http.md)、[Agent 与应用](../research_notes/内核%20永久%20冻结%20边界/agent-host-apps.md)。本次综合额外只核读了凭据管理、projects 入口及 Manifest，用于裁决笔记之间的分类矛盾。以下引用均指该提交的仓库源码，不引用历史记忆；“源码可达”“静态发现”不等于运行时复现。现状与目标明确分开，文中的迁移和验收均未执行。

## 一、两实体架构要求缩减责任，而不只是移动文件

当前注册体系仍有 system/local/application，公开名称中还存在 `runtime-callback`、`workspace-local`，Web/Notify/Agent 同列 builtin。目标不能沿用这个分类再改文案：两个 local registrations 应回到内核私有实现；Agent 仍是模块，只是获得发行身份绑定的可信宿主连接，不是第三类“运行能力”。当前 Agent 身份校验同时检查 workspace、moduleId、activeHash、builtin 及 approved builtin source；特殊启动配置不能由普通模块通过同名工具或参数取得。Pi 已在 Agent 进程中实例化，服务组合层通过 Agent client 路由调用，这是可保留的责任方向。([源码：`packages/contracts/src/steward/module-lifecycle.ts:4-8`](../packages/contracts/src/steward/module-lifecycle.ts#L4)；[`packages/engine/src/modules/steward/agent-application.ts:11-16`](../packages/engine/src/modules/steward/agent-application.ts#L11)；[`packages/engine/src/modules/steward/builtin/agent/runtime.ts:14-19`](../packages/engine/src/modules/steward/builtin/agent/runtime.ts#L14))

| 内核公共契约 | 模块身份、声明、路由、候选/检查/生命周期、owner 决定、凭据窄交付、有限事实；公开必要治理事实 | 全量 DB 行、页面 DTO、作者会话、官方包目录、Pi 参数 |

**应冻结“谁能决定”，而不冻结“今天如何实现”。** 作者和分发模块可以生成材料、维护需求及安装回执，但不能自报检查通过或批准自己；调度模块可以决定何时请求工作，但不能自报运行已停止；Notify 可以决定文案、渠道和摘要，但不能读取未获选的内核事实；Agent 控制 Pi handle，但共享资源释放由内核依据实际停止证据决定。这些边界已有生产机制依据，不需要先造插件、profile 或 Provider 注册框架。未来 Provider 在 Agent 内登记接入只是方向，本次不设计注册协议。([源码：`packages/engine/src/modules/steward/module-proposal.ts:126-149`](../packages/engine/src/modules/steward/module-proposal.ts#L126)；[`packages/engine/src/modules/steward/agent-delegation.ts:50-71`](../packages/engine/src/modules/steward/agent-delegation.ts#L50)；[`packages/engine/src/modules/steward/execution-state.ts:49-59`](../packages/engine/src/modules/steward/execution-state.ts#L49))

Web/Notify 的普通化必须同时改变身份、seed 和删除规则。当前 builtin seed 会重建缺失 builtin；入口删除还有独立禁止规则和 MCP 专名例外。因此只解除按钮或修改 `builtin` 展示不构成可移除。替换 Web 可复用现有 `listen` 归属与冲突检查，替换事实消费者可复用 `activity.consumer`；但前者不会自动改写 `web.page-set`，后者不会自动改写 `notify.send`。依赖者必须真实迁移，或经检查在原普通模块身份下替换实现；移除仍需 owner 决定、备份、依赖与 in-flight/unknown 守卫。独立 rescue/离线 CLI 保证没有 Web 时仍有管理途径，而非继续把 Web 名字作为信任根。([源码：`packages/engine/src/modules/steward/module-builtin.ts:90-125`](../packages/engine/src/modules/steward/module-builtin.ts#L90)；[`packages/engine/src/modules/steward/module-remove.ts:24-66`](../packages/engine/src/modules/steward/module-remove.ts#L24)；[`apps/server/src/app.ts:133-142`](../apps/server/src/app.ts#L133)；[`packages/engine/src/modules/steward/notification-facts.ts:54-79`](../packages/engine/src/modules/steward/notification-facts.ts#L54))

## 二、永久合同应覆盖最小信任闭环，不冻结相邻业务

### 最小公开合同：责任、输入输出、身份与权限

下表是**语义清单，不是新 API schema 或精确工具数**。每个写操作都需要可核对结果，读取也必须受 audience 和数据归属约束。可以合并同一责任下的操作，但不能把版本提交、授权、凭据和事实消费压成无类型的万能管理入口。

| 应冻结的合同 | 最小输入 → 最小输出 | 身份、权限与必须保留的保证 | 非目标 |
|---|---|---|---|
| 安装身份与契约发现 | 有界查询/指定模块或工具 → moduleId、选中版本、启停状态、工具输入输出声明、audience、契约绑定信息 | 目录来自内核权威身份；区分合法声明查阅与执行准入，元数据不授予权限 | 官方软件清单、origin 三分法、完整版本/运行历史、中文权限页 |
| 指定版本不可变源读取 | 模块身份、精确版本、合法材料范围 → 有界材料/可核验引用及不完整标记 | 读的是已存固定版本，不泄露其他应用私有数据或平台路径 | Provider cwd、Git 命令、builtin release 目录 API |
| 候选提交与受治理集合 | 自有材料或安全材料引用、目标、预期当前版本、授权关联、必要单项/原子集合约束、请求身份 → 稳定 receipt 与固定候选身份 | 真正提交者由路由提供；内核固化字节、校验目标和提交授权；集合在任何成员可能激活前绑定 | goal/examples/cause、作者 prompt、包 registry、任意宿主路径 |
| 检查及最终结果查询 | receipt/精确候选或集合 → 检查阶段、结论、范围、必要证据、审批引用、最终选中状态/未知 | 检查与固定材料绑定；提交者不能自报通过；查询原 receipt 不能触发新执行 | 全量 BuildReport、编译器日志格式、作者 transcript |
| 版本选择、启停、移除 | 精确目标和预期状态、必要风险/审批关联 → 实际状态、操作结果、数据处理及待决定事实 | 内核重验身份、依赖、in-flight、unknown、迁移和恢复；生命周期审批绑定具体 payload | Web/Notify 特权、MCP 例外、UI 推荐版本与业务补跑策略 |

| 凭据声明与敏感领取 | 凭据引用/批准声明 → 当前调用者获准的最小值或明确错误 | 当前真实 moduleId/hash、批准关系、不可记录敏感输入输出；不以 UI 自报替代授权 | OAuth provider 枚举、所有 refresh token 的普遍读取权 |
| owner 保管库窄管理 | 经 owner 授权的写入/删除/状态查询 → 无敏感值回显的 receipt、配置状态与受限声明关系 | Web 若继续代用户管理，必须保留公开窄路径；安全存储、锁和 refresh fence 留内核/可信保管边界 | 全局 UI DTO、通用表单 DSL、普通模块自行管理平台文件 |
| 有限观察与事实消费 | 有界观察；消费者选择；revision 下领取/ACK/失效核对 → 归属清晰的治理事实、实际 ACK IDs、持久撤回结果 | 事务内事实、单选消费者、moduleId/hash/revision、先私有持久接收再 ACK；ACK 不等于发送 | 通知文案、级别、静默时段、业务 readiness、任意事件总线 |

### 笔记中的 PRIVATE 不能抹去真实应用合同

**凭据管理必须保留公开窄路径。** 系统治理笔记将 set/remove/list 标为 PRIVATE，但 Web 实际调用这些工具；核读源码确认它们是 module-visible，且另有 `isEntryModule` 检查。存储是私有实现，不代表应用到保管库的协议也已私有。推荐把表单归应用，将内核永久义务收缩到 owner 授权管理、无值回显状态、受批准调用者领取及撤销/轮换一致性；若未来由其他受托应用承接保管，也必须先提供等价安全替代并迁完 Web，不能先删接口。现有 entry 推断也不自动构成充分 owner 授权，仍需解决第三节的授权门。([源码：`packages/engine/src/modules/steward/builtin/web/index.ts:101-104`](../packages/engine/src/modules/steward/builtin/web/index.ts#L101)；[`packages/engine/src/modules/steward/system/secrets.ts:33-69`](../packages/engine/src/modules/steward/system/secrets.ts#L33))

OAuth 的 Google/Microsoft 枚举、授权/token/refresh 产品协议不应永久冻结在内核，但**迁出有前置条件**。当前授权定义绑定 approved 版本，callback/refresh 会重验 definition、client 和 fingerprint，锁内避免删除或轮换后复活旧凭据；当前 unrecorded 调用禁止 async。普通应用工具没有同等不记录保证，不能把 token 经普通 invocation output 传输，再宣称凭据已经安全模块化。应先证明可用的敏感交付路径以及受托 OAuth 服务的最小授权，不在本次研究发明并冻结通用隐私框架；条件未满足前，现有安全路径继续承担责任，但不宣布其整个 schema 永久冻结。([源码：`packages/engine/src/modules/steward/oauth-definition.ts:18-51`](../packages/engine/src/modules/steward/oauth-definition.ts#L18)；[`packages/engine/src/modules/steward/oauth.ts:81-116`](../packages/engine/src/modules/steward/oauth.ts#L81)；[`packages/engine/src/modules/steward/module-calls.ts:358-389`](../packages/engine/src/modules/steward/module-calls.ts#L358))

有限事实保留“产生—领取—持久接收—ACK—撤回对账”的闭环，不保留通知产品 DTO。当前事实 upsert 不重开 consumed；consumer 首次 seed 不覆盖显式 null，选择切换有 revision；facts/ACK/withdrawals 检查真实 moduleId/hash；Notify 先 staged 再 ACK，恢复时核对撤回。这里的领取是选定消费者的接收权，不是新建可并发 claim 总线。ACK 不代表外部发送成功，withdrawal 不代表收回已发送消息。应移走 level/urgent/recipient、configure、reflection-retired 等业务字段和生产者，保留治理事实及持久 tombstone。当前无 TTL/自动清理，“有限类型与单条大小”不等于“有限磁盘”；不能自动删除未 ACK、幂等身份和仍用于旧消费者对账的 tombstone，也无需预建 retention framework。([源码：`packages/engine/src/modules/steward/notification-facts.ts:10-111`](../packages/engine/src/modules/steward/notification-facts.ts#L10)；[`packages/engine/src/modules/steward/builtin/notify/facts.ts:14-65`](../packages/engine/src/modules/steward/builtin/notify/facts.ts#L14)；[`packages/engine/src/modules/steward/reflection-retirement.ts:73-82`](../packages/engine/src/modules/steward/reflection-retirement.ts#L73))

### Manifest 是公开输入，不能把作者字段改称实现细节

生命周期笔记有将 entry/packages/limits/tests 格式称为 PRIVATE 的建议，协议笔记又把 settings/contributes/readiness 纳入候选。裁决是：**只要作者必须提交、内核仍验证或消费，它就是公开合同。** 可以不冻结当前布局和政策，但必须先移除内核依赖，或明确保留窄声明；不能原字段继续工作、仅把解释改成私有。当前 schema 为 strict，内核还会合并 params/settings、处理静态 triggers 和 lifecycle 标志。([源码：`packages/contracts/src/steward/index.ts:176-266`](../packages/contracts/src/steward/index.ts#L176))

|---|---|

## 五、消费者迁移完成且隔离验收后，才可宣布冻结

### Owner HTTP、救援与设备是支持边界，不自动并入模块合同

主 HTTP 宿主承担 API 鉴权、精确例外、路径归属和 proxy 凭据隔离。当前 proxy 移除 Authorization/Cookie、不转发 Set-Cookie、保留 pathname/query，应用不可达返回 503；`/ready` 只查 DB，不代表业务 ready。未配置 API key 时一般 middleware 不校验 key，这一部署事实必须明确，不能声称所有 `/api/*` 永远 fail closed。主宿主支持合同须单独列明，不把 Web 的页面/API、主题和 json-render 一起冻结为内核 API。([源码：`apps/server/src/app.ts:35-60,79-149`](../apps/server/src/app.ts#L35)；[`apps/server/src/middleware/auth.ts:31-46`](../apps/server/src/middleware/auth.ts#L31))

Agent bridge 有独立 loopback、拒绝 forwarded headers、run token scope、body/timeout 限制，不是免鉴权的 owner 文件/命令通道。Rescue 则独立 bearer、独立 listener，不依赖 Web/module routing；CLI 的授权来自本地文件所有权，写操作拿 runtime lock。它们均是真实支持面，应保留恢复与鉴权语义，不能因不是模块 API 而任意破坏，也不能把 HTML、日志 JSON、所有 CLI 子命令和内部 driver 一并承诺永久模块合同。([源码：`apps/server/src/routes/steward-agent.routes.ts:11-34`](../apps/server/src/routes/steward-agent.routes.ts#L11)；[`apps/server/src/rescue.ts:9-58`](../apps/server/src/rescue.ts#L9)；[`packages/cli/src/admin.ts:32-73`](../packages/cli/src/admin.ts#L32))

现有 `chrona.executor.v1` 是独立设备协议，包含 pair/poll/report/question/final/reconcile、generation/incarnation/assignment fences、stop proof 与 bounded journal；其远程模块 catalog 明确为空且禁止 direct calls。它必须保持自己的设备安全和兼容责任，但不等于未来通用 remote module host。本次不改第三方客户端，也不从共享 export 推导所有 executor/editor/Work schema 都是永久内核—模块 API。([源码：`packages/contracts/src/steward/executor.ts:7-53,112-113,136-160`](../packages/contracts/src/steward/executor.ts#L7)；[`apps/server/src/executor-router.ts:27-85,125-156`](../apps/server/src/executor-router.ts#L27))

| 事实保留与分页 | 有界读取、稳定 cursor、tombstone/幂等身份退出条件 | 当前无自动清理；不造 TTL 承诺，不访问真实 DB 推测规模 |
| 支持面清单 | 内核—模块、Agent 应用、owner/救援/CLI、设备各自兼容责任 | 分开列清，不因不是永久内核 API 而称为可随意破坏 |

四份笔记对责任方向基本一致，真正需要裁决的是“公共语义与私有实现混称”和“必要过渡能力被当成已迁出”。本报告已明确纠正凭据管理、projects 与 Manifest 的分类；剩余未决是上表的精确 schema、安全替代和持久状态迁移细节，不是是否保留 Web/Notify 特权或是否增加第三实体。仓库外消费者、真实数据积压、竞态/崩溃恢复、设备与第三方客户端的实际行为均未验证；静态报告不能给出生产利用率、迁移成功率或兼容性通过结论。

### 结语

永久冻结最有价值的结果不是“内核工具只剩某个数字”，而是未来修改软件来源、作者策略、日历规则、Web、通知和 Provider 时，不必修改内核既有公共义务。判断标准是：每项公开承诺是否有不能由普通模块安全承担的责任，是否有明确身份与授权来源，是否能在失败和未知状态下给出诚实结果。通过这一标准，既可以移除不必要的政策，又不会把预算、秘密和实际停止边界一并移走。
