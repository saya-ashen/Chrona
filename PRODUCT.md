# Product

## Register

product

## Users

Chrona is for people who plan real work on a schedule, delegate parts of that work to local or remote AI execution providers, and need to inspect what happened later. Users are often in a local development or power-user workflow: creating tasks, reviewing generated plans, scheduling blocks, approving interventions, diagnosing blocked runs, and resuming work with preserved context.

## Product Purpose

Chrona exists to connect task capture, planning, scheduling, execution, and review into one local-first control plane. Success means scheduled work can move forward safely, users can see current state without reading chat history, and every automatic action remains inspectable through tasks, plans, runs, approvals, traces, failures, and outputs.

## Brand Personality

Calm, precise, accountable. Chrona should feel like a reliable operating surface for work in motion: clear state, low drama, explicit recovery paths, and strong confidence that automation stays under user control.

## Anti-references

Avoid generic SaaS AI gloss: vague purple gradients, hero metrics, decorative dashboards, inflated claims, and motion that does not explain state. Avoid chat-first UI patterns that make schedule, plan, and execution state feel secondary. Avoid dense technical surfaces that hide current task, active node, blockers, review state, or next action.

## Design Principles

1. Make current state unmistakable: active task, active node, blocked or review state, and primary action must be visible before secondary detail.
2. Keep automation accountable: every AI action should expose source context, status, ownership, failure mode, and recovery path.
3. Favor inspectable density over decoration: dense panels are acceptable when they help users decide what to do next.
4. Preserve schedule-first control: chat and assistant surfaces support planning and execution, but calendar, task, plan, and run state remain primary.
5. Reduce uncertainty with precise copy: labels should describe what will happen, what is waiting, and what the user can do now.

## Accessibility & Inclusion

Use WCAG AA as baseline. Maintain readable contrast for dense text and muted labels, complete keyboard access for navigation and task actions, visible focus states, reduced-motion alternatives for every animation, and state indicators that do not rely on color alone.
