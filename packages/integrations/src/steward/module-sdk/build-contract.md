Chrona modules are long-running SDK processes. Import { on, chrona } from "chrona" and register on("tool", ...) handlers. The SDK connects through CHRONA_SOCKET. Register handlers before asynchronous initialization. Keep durable application state under chrona.paths.data and application files under chrona.paths.content when content is declared. These files are private; expose bounded tools for cross-application access. Never accept caller identity, host paths, Run tokens or privileged authority from arguments.

Authoring is an ordinary application's material workflow. The owner grants an exact candidate admission to the current submitter identity and target baselines through modules.admit-candidates. The author application prepares files under its own content directory, obtains immutable admitted source with modules.source, submits a complete fixed candidate set through modules.submit, and reads its durable receipt with modules.candidate-check. The kernel freezes source bytes and validates the entire set before checks and activation. A replay returns the same receipt; changed arguments conflict. A passing author test does not itself establish activation or approval. This material admission does not authorize automatic model execution or an unlimited repair loop. Agent is immutable and cannot be a candidate target.

Declare routed dependencies in uses; visibility determines the audience. uses is not a general runtime allowlist. Privileged capabilities enforce their own checked caller and approval boundaries. effects contains only network. Removed manifest fields triggers, settings, contributes and healthCheck are invalid. Application settings, readiness, notification wording and event registration belong to ordinary application tools. No public schedules or projects namespace exists. Observe kernel lifecycle/runtime evidence with modules.health and modules.diagnostics; application self-reported readiness is a separate application contract.

Discover tools through modules.tools and read their exact input/output and target identity before calling. For notifications use the ordinary notify.send contract. Register event definitions with events.register before events.emit; both are ordinary application calls. Persist registration and delivery receipts according to the application's actual contracts. Optional applications can be absent; report not_found/unavailable clearly and preserve other failures.

For bounded one-shot transformations declare agent.complete and agent.completion plus model: { tier, maxCalls, maxOutputTokens }. The Agent application owns model tiers, thinking and preferred timeout. Kernel moduleModel settings enforce atomic call and output limits, deadlines and daily budgets. Call chrona.call("agent.complete", { "command-key": key, prompt, "max-output-tokens": limit }) with a durable operation key, retain its operationId, then read chrona.call("agent.completion", { "operation-id": operationId }). A completed result contains { text, inputTokens, outputTokens }; a null result remains pending or unconfirmed, and failure reports a failed completion. Routed failures reject with ModelError; preserve its code and message. For example, model-budget admission rejects with code forbidden and a budget_exceeded reason in the message. The application owns bounded waiting and error handling. Treat model output as untrusted. Reuse the command key after a lost reply; do not automatically relaunch an uncertain completion. Agent contexts and Runs use the real routed caller; private Provider controls are not module tools.

Tests import { startModule, paths } from "chrona/testing", start the declared entry, send actual declared events and inspect replies/calls. Always stop the module in finally. Author tests run offline, including for network-capable modules; use fixtures and stubs and never contact a real model or account. Completion tests stub the routed contracts explicitly: startModule(entry, { stubs: { "agent.complete": () => ({ operationId: "fixture" }), "agent.completion": () => ({ result: { text: "stub", inputTokens: 0, outputTokens: 0 }, failure: false }) } }). Read node_modules/chrona/sdk.ts and testing.ts for the exact protocol. chrona/run-tests.sh runs the declared module tests. The preview helper provides local fixture responses; it is not a security sandbox.

Chrona validates the manifest, typechecks the entry, runs declared tests offline, checks startup/SDK connection without invented business events, and runs tests on copied or migrated application data before activation. Credential changes, data migrations and removal retain their actual approval boundaries. Stop uncertainty retains capacity. Never infer successful production behavior from a mock or installation check.

Dependencies use package.json with bun.lock or pyproject.toml with uv.lock. Chrona installs from lockfiles without accepting node_modules or .venv from candidate materials. Host programs belong in module.json packages for the current backend: ${BACKEND}. Derive application idempotency keys from the actual triggering operation and persist receipts before acknowledging work.
