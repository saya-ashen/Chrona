# Chrona web 页面设计规范

改这个模块（页面外观、布局、某个应用的专门页面）前先读本文件；改完按末尾清单自查。用户说过的页面偏好（`ui` 偏好）优先于本文件。

## 约束

- 聊天页（含新会话与会话详情）、今天页、登录页、活动页、应用列表、应用详情（全部标签与故障面板）、系统应用详情、设置与应用登记的页面共用 `pages.js` 的 PageView / Renderer（React + json-render，源码 `src/pages.tsx`，`bun build.ts` 生成并提交）；系统 spec 位于 `src/system/`，通过仅系统页挂载时创建的 adapter 访问现有数据 API。`app.js` 仅保留 shell 基础设施（认证、请求、路由、导航链接、退出、启动与单一 SSE 连接），不构造页面内容；登记页标题也由共享 renderer 绘制，路由错误使用系统 spec。`mountSystem` 按页面接收 typed params 对象，不序列化路由参数。聊天组件通过系统 host 订阅回复；样式统一在 `style.css`，不引入外部字体或 CDN（页面要能离线打开）。
- 静态页面不含数据；数据只来自 `/api/web`（带用户的 key）。`index.ts` 只发 `/app.js`、`/pages.js`、`/style.css` 和 `index.html`，新增静态文件要在那里登记。
- 中文优先。文案用用户的说法（应用、文档、对话、通知、需要你确认），不用内部名词（run、grant、token、hash、module）。
- web 不按模块名写专门页面：应用在 `on("activated")` 里调用 `web.page-set` 登记页面（组件目录见 `catalog.ts`，说明由 `web.catalog` 返回），web 统一绘制；共享显示需求在 `src/pages.tsx` 实现并加入 `catalog.ts`；只有系统页需要的交互组件留在 `src/system/`，不公开到 `web.catalog`。登记页只调用本应用工具，不获得系统 adapter；样式只用本文件的语义变量（见 [module-dependency-direction](../../../../../../../docs/zh/module-dependency-direction.md) §4）。

### 应用图片

`Image` 只接收本应用内容引用 `ref: "<本应用名>/<path>"`、`alt` 和可选的 `width`/`height`，不接收任意 `src`；`ref` 可用 `$state`/`$template` 绑定。`GET /api/web/pages/<module>/<page>/content?ref=...` 沿用入口认证，仅为已登记页面读取该应用自身的 PNG/JPEG/GIF/WebP。由于入口认证使用 Bearer 请求头，页面复用认证请求取得 Blob 后交给 `<img>`，切换图片或卸载时回收 URL；不把 key 放入 URL。加载中和失败时显示中文提示，图片宽度不超过容器。

## 性格

安静、清楚、可长时间使用的工作台，不是营销页：不用大面积渐变、装饰插画、超大标题和花哨卡片墙。当前状态和下一步操作永远不含糊。

## 颜色

只用 `style.css` 里 `:root` 的语义变量，功能代码里不写字面色值。浅色和深色是同一套语言（深色用中性石墨灰，不要整页偏蓝紫）。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#f7f7f5` | `#111216` |
| 卡片 / 画布 | `#ffffff` | `#1b1c22` |
| 正文 | `#18181b` | `#f4f4f5` |
| 次要文字 | `#71717a` | `#a1a1aa` |
| 分隔线 | `#dededb` | `#303138` |
| 主色（紫） | `#6257c7` | `#9b91ee` |
| 主色浅底 | `#eeecff` | `#282442` |
| 成功 | `#258451` | `#52b87b` |
| 警告 / 等你回复 | `#b76a00` | `#e8a23a` |
| 进行中 | `#2970a6` | `#62a7d8` |
| 危险 / 失败 | `#cf3f4f` | `#ee6674` |

状态不能只靠颜色表达：同时有文字（必要时加图标或位置）。“需要你确认”的事项用主色加明确文案，失败要带恢复操作。

## 形状、间距、字体

- 圆角：控件 6px，卡片 8px，弹层 12px；胶囊形只用于状态标签和紧凑筛选。不要卡片套卡片，能用分隔线或留白就不用边框。
- 间距以 4px 为单位：控件间 8px，内容块间 12px，区块间 24px；页面左右内边距桌面 24px、平板 20px、手机 12px。
- 字体 `system-ui, "Noto Sans SC", sans-serif`。页面标题 24px/600，区块标题 16px/600，正文 14px，辅助信息 12–13px。中英文同级同字号。
- 阴影只给浮层和菜单；常驻布局靠底色和分隔线。动效 120–240ms，尊重 `prefers-reduced-motion`。

## 操作

每个区域只有一个视觉上最强的下一步：主操作实心主色，次操作描边，三级操作纯文字；只有真正删除类操作用危险色。选中态用主色浅底，不能和主按钮长得一样。需要用户决定的事项放在页面最上方、首屏可见。

## 响应式

在 1440×900、1024×768、390×844 三个尺寸检查。手机不能横向滚动；标题可以折两行再截断；先隐藏重复说明，再压缩核心内容；触控目标至少 40×40px，手机主操作高 44px。

## 可访问性

正文和必要的次要文字达到 WCAG AA 对比度；必要说明、做决定要看的时间、错误恢复提示不要用浅灰。两种主题下焦点框都清晰可见。

## 自查清单

- 不读完每个标签，也能看出当前状态和需要我做什么吗？
- 每个区域是否只有一个主操作？
- 能用分隔线代替嵌套卡片吗？
- 浅色和深色看起来是同一个产品吗？
- 390px 宽时标题、日期和主操作都还清楚、没有横向滚动吗？
- 空、加载中、出错、等待、完成几种状态都有合适的样子吗？
