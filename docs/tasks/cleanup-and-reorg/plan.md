## 每阶段门禁

1. `bun run lint`：固定本任务基准，明确 ratchet 通过只表示不新增债务。
2. `bun run lint:warn`：记录全库存量诊断，不将其与 ratchet 混同。
3. `bun run typecheck`、`bun run check:guardrails`、`bun run check:boundaries`。
4. `bun run verify:slice`：完整执行仓库规定入口，但不替代全量测试。
5. `bun run test`：Bun 与 API 全量入口，保存实际测试文件清单和退出码。
6. `bun run build`、`bun run build:smoke`：原生发行构建与隔离冒烟。

完全相同且已通过的检查不重复执行；需要合并重复内部步骤时记录覆盖关系。检查使用全新临时数据，不读取真实数据库或凭据。重型任务按现有规定限内存并串行。任何失败留下完整日志和最小复现，既有失败与新失败分开报告；环境无法补齐、跨越公开合同或需真实数据转换时记录硬阻塞并停止依赖阶段。

## 应用发行策略

- 默认预装：pi、web、notify、author、mind、chat。
- 随发行可选：qq。
- 保留源码与适用离线检查，不自动运行或进入发行：events、files、mcp、memory-local、remind、remote-execution。
- 没有受跟踪源码的 coding/coding-web 残留不新建应用仓库。
- 远程命名规则不证明 commit 已发布；repository:null 不能被猜测地址替换。无已核验远程时使用本地历史和离线 bundle。

## 提交与最终报告

每个通过适用检查的切片可以独立提交，每阶段进入下一阶段前完成完整门禁。无改动不作空提交，最终保留任务分支，不自动合并 main、不推送。最终报告列出：基准和最终提交、所有独立应用路径/历史/版本/远端状态、固定输入机制、删除依据与净行数、新目录与例外、测试迁移映射、全部验证和跳过项、实际 chino 包与应用状态、备份和未完成项。

## 恢复入口

恢复时先读同目录 `progress.md` 和门禁日志，核对实际 git status/HEAD。不得重跑已发生的外部动作或历史数据转换。原工作区仅用于读取本次用户输入和历史部署线索。
