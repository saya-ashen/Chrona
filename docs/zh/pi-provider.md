# Pi Provider（实验性）

Chrona 支持独立的官方 **Pi CLI Provider（`pi`）**，不替换 Oh My Pi（`omp`）。
Chrona 服务所在机器需预装 **Pi ≥ 0.85.0**；Chrona 不打包 Pi，稳定默认推荐仍为 Codex。

## 配置

1. 先在终端完成 Pi 登录、模型配置，确认模型可用。
2. 打开 **设置 → AI 客户端 → 添加客户端 → Pi**。
3. 模型留空使用 Pi 默认值；覆盖时填写精确 `provider/model-id`，或分别填写模型提供商与模型 ID。
4. 可指定 Pi agent 目录（默认 `PI_CODING_AGENT_DIR` 或 `~/.pi/agent`）和工作目录。
   工作目录决定项目扩展、技能、上下文发现位置和文件工具作用位置，默认 Chrona 服务 cwd。
5. 测试连接后保存并选择功能绑定。连接测试会发送小型真实模型请求，可能产生费用。

认证与模型地址由 Pi 管理，无需向 Chrona 复制 API Key。服务进程必须能够找到 `pi` 并访问对应配置。

## 行为边界

- **任务执行**：加载本机 Pi 配置、扩展、技能及项目上下文，遵循 Pi 已保存的信任规则，不自动批准信任。
  扩展拥有服务用户权限，并非沙箱；应选择可信目录和扩展。
- **计划、Goal 复盘、结果整理、只读追问**：禁用扩展/技能/提示模板/主题/上下文自动发现，仅开放指定结果工具，
  关闭自动重试和压缩。模型需能在不加载任意扩展时使用（内置提供商或 `models.json`）。
  Pi 认证辅助命令仍可能执行；此隔离不等于操作系统沙箱。
- **确认框**：支持单次批准/拒绝。不支持选择、多行编辑、文本输入和启动期交互，遇到这些请求停止。
  Pi RPC 本身不支持 TUI 自定义组件，可能返回无 UI；依赖此类组件的扩展不适合无人值守执行。
- 扩展或协议故障直接停止，不擅自禁用扩展重试、切换运行方式或替换模型。

Chrona 桥接文件、会话、操作占用记录放在自己的数据目录 `providers/pi` 下，不修改 Pi 用户配置，不接管交互会话。
运行令牌保留在父进程，不写入 Pi 命令行、扩展源码、工具目录或模型提示。执行终止动作必须获得引擎持久化确认。
使用 `agent_settled` 判断 Pi 本轮真正结束，不把可能发生重试的 `agent_end` 当完成。
在此之前 IPC EOF 或进程退出（包括退出码 0）均视为失败，不能等同模型完成。
桥接额外 stdio 使用非阻塞 Socket，而非可能阻塞 Node 退出的文件流；启动可取消，进程和工具清理有界。
结果整理另有 compose 5 分钟、review 1 分钟的时限；已校验候选先保存，review 异常时回退候选，不重跑任务执行。

支持续接 Chrona 自有历史会话，**不支持运行中进程恢复、断线重连、事件重放或不确定操作自动重试**。
发现中断遗留会话锁时应使用新上下文，不应在其他进程可能仍运行时直接删锁。

当前验证基线为 Linux / Pi 0.85.0。macOS、Windows 及任意第三方扩展组合尚未认证；
Windows 取消仅保证尝试终止 Pi 本身，不保证清理所有后代进程。
详细协议边界、测试命令见 [英文说明](../en/pi-provider.md)。
