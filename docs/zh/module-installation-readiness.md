# 应用安装与就绪

安装、批准、激活、进程连接和业务可用分别判断。当前生命周期合同见 [API 规范](kernel-api-design.md)，实际入口见[运维](operations.md)；不从旧 readiness 投影或应用自报推导成功。

安装检查保留 manifest 与工具合同、入口类型、冻结依赖、完整不可变材料、必要数据副本与迁移检查、进程启动和 SDK 通信。失败保留实际原因、旧版本与真实数据；数据副本测试不应把私人内容写进公开构建报告。

安装器不编造业务参数、caller、定时事件或外部效果来证明可用。应用在自己的仓库执行测试、类型检查和调用方影响检查，Author 保留实际证据；作者测试覆盖真实输入及幂等行为；启动和协议检查只能证明相应层次，不能证明页面或业务操作已完成。

当前工具发现与健康读取使用 `modules.describe`、`modules.health`，按实际合同选择参数。运行中、启动中、停止未知、等待恢复和配置暂停分别显示；健康证据绑定实际应用、版本及激活。自检不发送消息、修改项目或请求付费模型，不清除未知外部效果，也不替代实际业务恢复验证。

本次清理删除了无生产消费者的 `module-readiness.ts`；旧 `chrona.reportHealth()`、`modules.report-health` 与 Coding 试用说明从本文件 Git 历史查阅，不作为当前接入指导。新需求的产品验收仍须独立执行；[交付结果](../../../chrona-module-author/docs/app-authoring-delivery.md)说明证据边界。
