# 模块平台首次真实端到端运行（2026-10-20）

代码版本：`ac6bdeb5`（运行中发现的问题在 `9e7d6220` 修复）。临时数据目录、全新数据库；Provider 为 Pi 1.3.0（未包装二进制）+ `openai/gpt-6.1-sol`，bwrap 沙箱。单次运行，不代表统计结论。

## 过程

| 步骤 | 用户输入 / 动作 | 实际结果 |
|---|---|---|
| 1 | 聊天："每5分钟检查一次，自己记着次数，每累计到第2次就提醒我…并告诉我这是今天第几次" | Pi 建事务，写 Python 模块 `movement-reminder`（清单、`main.py`、`test_main.py`），`chrona_propose` 提交；沙箱测试通过；生成审批（联网：否） |
| 2 | 批准 | 生成 `module` 调度；两次触发后发出"该起来活动一下了，这是今天第1次提醒。" |
| 3 | 聊天："改成每累计3次才提醒，晚上22点以后就别提醒了" | Pi 提交第二版（新 hash），自行写了旧状态迁移（只迁移未消费余数）与新测试 |
| 4 | 批准第二版 | 新版接上旧数据（`rule_version: 2`），第 3 次检查后发出"第2次提醒" |

批准后的 5 次模块触发**没有创建任何 Provider 运行**（Run 总数始终为 5，全部来自两轮对话与构建）。四次 Provider 运行合计约 88 万 token。

Pi 自己写出的值得注意的做法：文件锁、原子写入、按 `firedAt` 的单调水位去重、按 Asia/Shanghai 每日重置、提醒 key 含日期与序号。

## 发现并已修复

1. Pi 用 `chrona_schedule_cancel` 取消了旧版本的模块调度（想"先暂停旧版"），导致模块显示 active 却无调度。现在模块调度只能经启用/回滚/执行器失败暂停改变。
2. 第二版只改代码、清单不变，审批预览几乎为空。现在预览包含逐文件代码差异，过长时截断并提示检出。

## 运行环境上的发现

- 个人 Pi 包装脚本会被 Chrona 的资源检查拒绝（`Unexpected Pi command resources`），须使用服务专用的未包装 Pi 可执行文件——与 operations.md 的要求一致。
- 本次 `CHRONA_STEWARD_PI_AGENT_DIR` 临时指向个人 `~/.pi/agent` 以复用认证；正式部署应按 operations.md 准备服务专用 profile。
