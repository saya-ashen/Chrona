# 安全机制简化：保留可靠性，砍掉假隔离

状态：2026-11-02 讨论、2026-11-03 用户确认方向与顺序（3 → 2 → 5）。§3.1–§3.3 均已实现（2026-11-03）。与 [module-dependency-direction.md](module-dependency-direction.md) 并列。

## 1. 结论

模块以同一个 OS 用户运行（`trusted-local`，已部署），manifest 与路由层面的权限挡不住恶意代码，只能约束守规矩的代码，实际作用是防误操作与留痕。现有体系却按"防攻击"建造：`uses`、`visibility`、`callers`、`effects`、绿/黄/红定级、AI 复核、审批习惯、5 种 grant 模式、2 种更新复核模式……复杂度全付了，安全收益很少。

证据（2026-10-22 至 11-02）：84 次审批全部批准、0 次拒绝，中位处理时间 0.6 分钟；AI 复核 34 次通过、9 次升级，从未拦下任何东西。

## 2. 保留

- 版本、hash 与回滚；迁移前备份；测试、类型检查、启动检查；预算。
- 凭据不进 prompt。
- 运行时的对外动作审批：发外部消息、下单、删数据等由模块或 Provider 在执行时发起的审批。

## 3. 简化（按顺序）

### 3.1 模块启用：检查通过即自动启用（第 3 项）

- 构建检查（测试、类型检查、调用方检查、连续性、key probe）全部通过的版本**自动启用**，事后以 digest 通知告知变更与回滚方式。不出审批卡。
- 只在以下情况**问一次**：
  1. 需要迁移已有数据（schema 升级且有数据），或回滚需恢复旧数据快照；
  2. 新增凭据（`secrets` 增加）或新的外部账户授权；
  3. 删除应用。
- 删除：绿/黄/红定级（`approval-level.ts` 的定级与 `Approval.level`）、AI 复核（`approval-review.ts`、模型设置中的 `review`）、审批习惯（`approval-habits.ts`）、`moduleUpdateReview`（`checks-only`）、`activate_module` 的长期授权与自动授权逻辑（`module-auto.ts`）、按能力扩张判定的资格检查。
- 全新应用首次启用同样自动启用（用户 2026-11-03 确认）。内置模块是随发版的可信代码，新增凭据不问（凭据仍由用户在应用页填写），只在迁移数据时问。
- 构建检查中 key probe 失败（重复投递会产生重复效果）现在直接拒绝该版本，而不是转为人工审批。
- Chrona 暂停、恢复应用直接生效并记入审计。
- 运行时审批不再分级；卡片只保留标题、说明与详情；网页、QQ、MCP 任何入口都可批准或拒绝（用户确认，删除"红色只能在网页批准"）。

### 3.2 `uses`、`callers`、`visibility` 降为契约（第 2 项）

- **`callers` 删除。** 它唯一的作用是"只有这些模块能调我"的名单。任何模块都可调用 `visibility` 含 `modules` 的工具；events 的订阅回调、notify 的渠道投递、mind 的 attention 等只需对模块可见。存储中的旧 manifest 解析时丢弃该字段。
- **`uses` 不再做运行时准入。** 它仍是契约：生成类型检查用的调用声明、影响分析、依赖签名（`activated` 再投递）与页面上的能力说明。`uses: ["*"]` 仍表示入口模块代表用户调用 `owner` 工具。
- **`visibility` 保留**，表示工具面向谁（Agent、用户入口、其他模块、内核），决定各处工具目录与名称解析；它是接口的一部分，不是权限名单。
- 凭据（`secrets`）的按名读取不在此项范围内。

### 3.3 构建会话与主会话使用相同的读取工具（第 5 项）

构建会话可搜索并调用与普通会话相同的应用工具（`m_*`，含用户数据的读写工具——没有可靠的只读标记，按可信本地模型不再区分）；Chrona 自身工具只有 `chrona_reply`，因为构建只向发起它的会话汇报。反思会话仍只用自己的工具。

### 3.4 授权只有"允许"和"问"（2026-11-03 架构审查第 1 项）

- 授权模式只剩 `allow` 与 `ask`：原 `auto`、`notify_after`、`preapproved` 合并为 `allow`，删除 `never`（`change_credentials` 默认改为 `ask`）。
- 一次性授权保留：用户"仅这次"批准后，等待的运行或目录挂载凭它执行一次。
- 模块启用不再经过授权：启用审批通过后直接启用，不生成、不检查 `activate_module` 授权；删除"策略禁止启用"检查与已有的 `activate_module` 授权。
- 存储迁移：旧模式按上述合并改写，`never` 改为 `ask`，`activate_module` 授权删除。

## 4. 规则

- 每项简化在同一次改动中删除被替代的代码、测试、文档、提示词与契约字段，不保留兼容层。只有已存储数据仍需解析时才保留，并以一行注释说明。
- 第 4 项（应用自己提供页面）已由"应用向 web 登记页面"完成；第 1 项（`trusted-local`）已部署。
