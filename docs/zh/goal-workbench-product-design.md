# Goal Workbench 产品设计

状态：已确认的目标设计，尚未全部实现。

本文定义 Chrona Goal Workbench 的产品定位、信息架构、资产生命周期、交互模式与安全边界。它是 [`Long-Horizon Goals, Triggers, and Task Occurrences`](../en/long-horizon-goals-and-triggers.md) 中 Goal 产品架构的细化设计；若两者对 Workbench 的细节描述不同，以本文的资产使用区设计为准，Goal 生命周期、执行、权限和审计边界仍以长期 Goal 设计为准。

## 1. 产品定位

Goal Workbench 是 **Goal 产出资产的实际使用区域**，不是 Task 看板、Goal 状态控制台、通用网盘或持续运行的 AI Agent。

用户在这里：

- 浏览已经沉淀为 GoalAsset 的正式资产；
- 整理 Task 新结果中的候选资产；
- 阅读、填写、编辑或运行资产；
- 管理草稿、正式版本和历史版本；
- 下载源文件或导出消费格式；
- 以明确资产版本为输入，发起有界 AI 修改 Task。

Goal 的生命周期、成功标准、当前工作和历史仍由 Goal 的其他一级页面负责。Workbench 只在必要位置显示来源 Task、关联版本和运行状态，不复制第二套 Goal 或 Task 生命周期。

## 2. 设计原则

1. **先使用成果，再管理过程。** Workbench 首屏优先展示可打开、可填写、可编辑或可运行的资产，而不是 Task 数量和执行统计。
2. **正式资产与待整理结果分离。** Task Result 不会自动成为正式 GoalAsset。
3. **资产身份由用户确认。** AI 可以建议新建资产或追加版本，但不能直接决定资产归属。
4. **正式版本稳定。** 自动保存只更新草稿；只有明确提交或确认后才产生新的正式版本。
5. **来源不可丢失。** 每个正式版本都能追溯到父版本、用户修改或来源 Task/Run/Result/Artifact。
6. **Task 使用冻结输入。** 新建 Goal Task 自动捕获全部未归档正式资产的有界元数据；Agent 按相关性读取正文，读取固定在捕获版本，用户无需逐 Task 选择资产或版本。
7. **能力按资产类型设计。** 文档、表单、页面和通用文件不强行使用同一种编辑器。
8. **生成页面与 Chrona 宿主隔离。** 风险警告不能替代最低限度的技术隔离。
9. **不把 Workbench 扩张成通用项目管理或 Office 套件。** 首版只实现持续使用 Goal 成果所需的最小完整闭环。

## 3. Goal 页面关系

Workbench 是 Goal 内独立的一级页面。目标导航保留稳定的信息所有权：

| 页面 | 所有权 |
| --- | --- |
| Overview | Goal 当前状态、唯一下一步、重要变化和风险摘要 |
| Work | 当前、等待和即将开始的有界 Tasks |
| Workbench | 正式资产库、待整理结果和单资产使用工作台 |
| Success criteria | 成功标准、证据、冲突和用户确认 |
| History | 生命周期、决策、Task 转换和资产版本事件 |

这相当于把原先宽泛的 `Results` 责任细化为资产使用闭环：新结果先进入 Workbench Inbox，确认后进入资产库。已完成 Task 和普通运行历史不因 Workbench 的存在而迁入资产库。

Goal 的固定页头在这些页面间保持一致，继续显示：

- Goal 名称；
- 生命周期状态；
- 规则推导出的唯一主要操作；
- Goal 管理菜单。

Workbench 不自行决定 Goal 的主要下一步，也不赋予 AI Goal 生命周期权威。

## 4. 顶层信息架构

Workbench 有两个稳定视图：

```text
Workbench
├── 资产库
│   ├── 最近使用
│   └── 全部资产
└── 待整理 Inbox
    └── Task 结果中的候选资产
```

### 4.1 默认入口

- 进入 Workbench 默认打开 **资产库**。
- Inbox 有未处理候选项时显示数量徽标，但不强制跳转，避免打断用户使用已有资产。
- 从资产详情返回时，恢复原来的标签、搜索词、筛选条件、排序和滚动位置。
- 通过深链接打开资产或 Inbox 项时，保留 Goal、语言环境和返回位置。

### 4.2 空状态

资产库和 Inbox 都为空时，页面解释 Workbench 只保存正式资产，并提供：

1. **查看 Task 结果**：查找可整理的已接受结果；
2. **创建产出型 Task**：创建一个有明确可交付物的有界 Task。

空状态不默认提供任意本地文件上传，以免 Workbench 退化为通用网盘。后续若支持导入，必须把“外部导入资产”和“Task 产出资产”的来源明确区分。

## 5. 资产库

### 5.1 默认编排

资产库采用类似 Office 首页的视觉浏览模式：

```text
最近使用
[预览卡] [预览卡] [预览卡]

全部资产                 [搜索] [类型] [来源] [状态] [排序]
[预览卡] [预览卡] [预览卡]
[预览卡] [预览卡] [预览卡]
```

默认先显示最近使用资产，再显示全部资产网格。首版不增加文件夹和用户标签，避免与 Goal、来源 Task、资产类型和版本形成互相竞争的分类体系。

### 5.2 搜索与筛选

首版支持：

- 资产名称全文搜索；
- 资产类型筛选；
- 来源 Task 筛选；
- 状态筛选，例如有草稿、AI 修改运行中或异步处理失败；
- 最近修改时间排序。

筛选结果为空时保留当前查询条件，并给出清除筛选操作，不显示成“Goal 尚无资产”。

### 5.3 轻量预览卡片

卡片默认只展示扫描资产所需的信息：

- 真实内容预览或稳定类型占位图；
- 资产名称；
- 资产类型；
- 当前正式版本；
- 最近修改时间；
- 必要状态，例如“有未提交草稿”“预览生成失败”或“AI 修改运行中”。

卡片悬停或聚焦时只提供：

- 打开；
- 下载源文件；
- 更多菜单。

重命名、导出、版本历史和归档放在更多菜单或资产详情中，避免九宫格变成高密度管理面板。所有悬停操作也必须能通过键盘聚焦和移动端菜单访问。

### 5.4 缩略图

缩略图按资产类型异步生成：

| 类型 | 缩略图策略 |
| --- | --- |
| Document | 渲染当前正式版本首屏 |
| Form | 渲染字段结构摘要，而不是用户 Submission 内容 |
| Page | 在隔离运行环境中生成截图 |
| File | 支持格式使用内容预览，不支持时使用类型占位图 |

缩略图随正式版本异步更新，不阻塞版本提交。生成失败时继续允许打开源内容，并显示重试入口。旧缩略图若仍被展示，必须标明它对应旧版本，不能让用户误以为预览已经更新。

## 6. 资产与版本模型

### 6.1 资产身份

同一逻辑资产在资产库中只占一张卡片。后续 Task 对它的修改通常成为新版本，而不是创建“最终版 2”之类的新卡片。

资产名称独立于：

- 原始文件名；
- 来源 Task 标题；
- Artifact 名称。

AI 可在 Inbox 提议名称，用户确认时可修改。重命名不产生内容版本，但记录作者、时间和审计事件。

### 6.2 正式版本和草稿

```text
当前正式版本
    ↓
自动保存草稿
    ↓
用户明确提交
    ↓
产生新的正式版本
```

资产卡片始终代表当前正式版本。存在草稿时显示“有未提交草稿”，但：

- 不用草稿替换卡片的正式缩略图；
- 默认下载不下载草稿；
- 最近使用可以让用户直接继续编辑草稿。

每个正式版本至少记录：

- 版本号或稳定版本标识；
- 父版本；
- 作者和提交时间；
- 变更说明；
- 修改来源：手工编辑、AI Task、恢复历史版本或外部导入；
- 来源 Task、Run、accepted Result 和 Artifact（若适用）；
- 内容哈希和可验证的来源关系。

Task 的 accepted Result 和 Artifact 保持不可变。GoalAsset 版本引用或派生这些来源，不能反向覆盖原始结果历史。

### 6.3 手工修改

用户直接编辑文档或表单设计后提交新版本，不创建伪 Task。版本历史记录手工作者、父版本和变更说明。只有需要 AI 或外部执行的修改才创建有界 Task。

### 6.4 并发冲突

草稿绑定开始编辑时的基础版本。提交时使用乐观锁：

```text
草稿基于 v5
当前正式版本已经是 v6

[查看差异] [基于 v6 重新应用] [另存为新资产]
```

系统不得用最后写入静默覆盖 v6。首版不引入完整分支模型；无法安全重放的草稿可以另存为新资产。

### 6.5 恢复历史版本

恢复不会改写历史，也不会把 `current` 指针简单移回旧版本。恢复操作创建一个新的正式版本：

```text
v3 → 恢复 → v8（内容来自 v3）
```

v8 记录恢复来源、操作者和时间。v4 至 v7 继续可查。

### 6.6 归档和删除

默认移除操作是可恢复归档：

- 从默认资产网格隐藏；
- 保留来源 Task Result、Artifact 和版本历史；
- 可从归档视图恢复。

永久删除只允许用于没有正式版本和外部引用的草稿，并要求二次确认。任何删除或归档都不能破坏 Goal 成功标准证据、accepted Result 或 Task 审计链。

## 7. 待整理 Inbox

### 7.1 候选资产粒度

一个 accepted Task Result 可以产生多个候选资产，同时保留共同来源分组：

```text
Task「市场调研」结果
├── 调研报告.docx → 建议创建新资产
├── 数据.csv       → 建议创建新资产
└── Dashboard      → 建议成为「市场看板」v3
```

候选资产不限于已有文件。无文件但具有稳定结构或可渲染内容的 accepted Result，也可以派生为 Document、Form 或 Page。派生过程必须保存 selector、内容哈希和来源。

### 7.2 AI 可解释建议

AI 可以为每个候选项建议：

- 新建资产或成为现有资产的新版本；
- 建议资产名称；
- 建议目标资产；
- 匹配理由；
- 变化摘要；
- 置信度。

低置信度默认建议新建资产，不自动合并。用户必须能够：

- 接受建议；
- 选择其他现有资产；
- 改为新资产；
- 不加入资产库，仅保留原结果。

AI 建议不直接产生正式版本，不改变资产身份，也不修改 Goal 生命周期。

### 7.3 类型化差异审查

建议追加为现有资产的新版本时，确认前展示适合该类型的变化：

| 类型 | 审查内容 |
| --- | --- |
| Document | 文本增删、结构变化和语义摘要 |
| Form | 字段增删、字段类型、必填、校验和布局变化 |
| Page | 前后截图、文件变化、入口和运行依赖变化 |
| File | 文件名、MIME、大小、哈希及格式支持的内容差异 |

差异摘要不能替代真实预览。用户确认后才创建新版本；拒绝建议不会删除 accepted Result。

## 8. 单资产工作台

### 8.1 桌面布局

桌面端使用可折叠三栏：

```text
┌ 返回资产库 / 名称 / 模式 / 下载 / 提交新版本 ┐
├────────┬────────────────────────┬──────────────┤
│资产导航│        内容画布         │上下文与操作   │
│可折叠  │ 文档 / 表单 / 页面      │可折叠         │
│        │                        │版本、来源、AI │
└────────┴────────────────────────┴──────────────┘
```

- 左栏用于在当前 Goal 的资产间切换；
- 中栏给内容最大可用空间；
- 右栏显示版本、来源、草稿状态、Task 运行状态和 AI 修改入口；
- 两个侧栏都可折叠，折叠状态在同一设备上保留；
- 页面不得因固定三栏产生横向滚动。

### 8.2 移动端

移动端以浏览和填写为先：

- 资产库使用双列卡片；
- 资产详情使用单栏内容；
- 资产导航和上下文分别进入抽屉；
- 支持阅读、下载、轻量文档编辑、Form 填写和 Page 运行；
- 复杂表单设计等高密度操作明确提示到桌面继续；
- 不通过隐藏主要操作来模拟桌面等价能力。

## 9. 类型化使用体验

### 9.1 Document

Document 是结构化轻文档，而不是完整 Word 替代品。首版支持：

- 标题和段落；
- 有序与无序列表；
- 表格；
- 图片；
- 链接；
- 直接编辑；
- 对选区或整篇发起 AI 修改 Task。

首版不承诺分页、页眉页脚、复杂打印布局或实时多人协作。

### 9.2 Form

同一 Form 资产明确分离两种模式：

```text
填写模式 → 创建不可变 Submission
设计模式 → 编辑草稿 → 提交 Form 新版本
```

Submission：

- 归属于 Form 的具体版本；
- 不修改 Form 定义或当前版本；
- 可查看和导出；
- 默认不在九宫格中创建独立资产卡片；
- 可明确用于创建后续 Task、派生新资产或加入 Goal 上下文。

设计模式修改字段、校验和布局，提交时遵守正式版本和冲突规则。

### 9.3 Page

Page 支持在 Workbench 中运行交互页面。首版暂不实现细粒度网络、数据和动作能力授权，但必须满足最低隔离边界：

- 运行前显示明确风险警告；
- 使用隔离 iframe；
- 不启用 `allow-same-origin`；
- 可按实际需要开放 `allow-scripts`、`allow-forms` 和 `allow-modals`；
- 生成页面不能访问 Chrona DOM、同源 localStorage、访问密钥或宿主执行权限；
- 外部副作用仍须通过 Chrona 有界 Task 和既有审批边界完成。

建议的最低策略示例：

```html
<iframe sandbox="allow-scripts allow-forms allow-modals">
```

风险警告不是用户对任意权限的授权。未来增加网络、GoalAsset 数据访问或外部动作时，必须设计显式能力声明、用户批准和审计机制。

### 9.4 File

PDF、图片、CSV、ZIP 和其他非一等类型使用通用 File 资产兜底：

- 浏览器安全支持时提供预览；
- 不支持时显示稳定类型信息；
- 始终允许下载原文件；
- 有可靠转换器时提供导出；
- 不假装提供并不存在的原生编辑能力。

电子表格首版仍按 File 处理；未来只有在网格编辑、公式、导入导出和版本 diff 形成完整闭环后，才升级为一等类型。

## 10. AI 修改与后续 Task

### 10.1 AI 修改流程

Workbench 不创建 Goal 级持久 provider 会话。AI 修改复用 Chrona 有界 Task：

```text
资产 v5
→ 用户描述修改目标
→ 创建绑定 v5 的 AI 修改 Task
→ Task 执行并产生 accepted Result
→ 候选结果进入 Inbox
→ 类型化差异审查
→ 用户确认
→ 资产 v6
```

右侧面板显示 Task 的真实状态和真实下一操作，例如提供输入、审批、重试、查看进度或审查结果，而不是伪造 Workbench 内部运行状态。

### 10.2 Task 自动使用资产

创建 Goal Task 时，Chrona 自动把所有未归档、已批准资产的有界元数据写入不可变 Goal context snapshot。正常流程不提供逐 Task 资产复选框或版本选择器：

- 快照包含不透明 `GA...` 引用、标题、稳定描述、用途、技术类型、正式版本和更新时间，不包含正文或后端 ID；
- Plan 与执行 Agent 先看到完整元数据目录，只有正文会实质影响计划或当前节点时才按需读取；
- 精确读取解析到 Task 捕获的正式版本，资产后续发布、归档、Retry 或 Replan 都不会改变既有 Task 输入；
- Draft 在发布前不进入新 Task；发布和归档只影响之后创建的 Task；
- Task Workspace 区分“已捕获”和“已读取”，Result 只展示实际成功读取的资产及捕获版本；
- `GA...` 正式知识与不可变 `GR...` Accepted Result 历史始终分离。

## 11. 下载与导出

下载和导出是两个不同动作：

- **下载源文件**：取得该版本保存的原始内容；
- **导出**：转换为面向消费的格式。

示例：

| 资产 | 下载 | 导出 |
| --- | --- | --- |
| Document | Markdown 或规范源格式 | PDF、DOCX |
| Form | Form 定义 JSON | 可分发表单格式（若支持） |
| Submission | 原始提交 JSON | CSV、JSON |
| Page | 页面源代码包 | 静态包（若兼容） |
| File | 原文件 | 受支持的转换格式 |

当前版本和历史版本都能下载或导出，操作前明确显示版本。异步导出显示处理中、完成和失败状态；失败不使资产本身不可用。

## 12. 状态与恢复

Workbench 至少覆盖以下可见状态：

| 状态 | 用户可见行为 |
| --- | --- |
| 加载中 | 保留页面结构，不用整页空白替代 |
| 资产库为空 | 引导整理 Task 结果或创建产出型 Task |
| Inbox 为空 | 说明没有待确认候选项，返回资产库 |
| 有草稿 | 卡片标记并可继续编辑，不替换正式版本 |
| 预览生成中 | 使用类型占位，不阻塞打开 |
| 预览失败 | 可打开内容并重试预览 |
| 导出处理中 | 显示进度或排队状态，可离开页面 |
| 导出失败 | 显示原因和重试，不标记资产损坏 |
| AI Task 运行中 | 链接真实 Task Workspace |
| AI Task 等待输入/审批 | 显示真实所需动作，两个状态文案不可混同 |
| 版本冲突 | 阻止静默覆盖，提供差异和恢复路径 |
| 资产已归档 | 默认网格隐藏，可在归档区恢复 |
| 源内容不可用 | 保留来源和元数据，明确说明不可预览或下载的原因 |

## 13. 单用户边界

首版是单用户 Goal 工作区，不包括：

- 公开分享链接；
- 实时多人编辑；
- 评论线程和成员提及；
- 资产级角色或权限；
- 多人冲突合并。

本地运行不等于可以忽略来源、版本或安全边界。即使只有一个用户，AI Task 和用户草稿也会产生并发版本冲突。

## 14. 非目标

首版明确不做：

- 通用 Kanban 或项目管理；
- 通用网盘和任意文件同步；
- 完整 Word、Excel 或低代码页面搭建器；
- Goal 持久 AI 会话；
- 把全部 GoalAsset 正文预注入每个 Task，或把 Workbench 变成逐 Task 上下文选择器；
- AI 自动确认资产身份、覆盖正式版本或变更 Goal 生命周期；
- 生成页面直接运行在 Chrona 同源宿主环境；
- 用可撤销提示代替正式版本确认和审计。

## 15. 产品验收标准

实现完成必须通过正常用户路径验证，而不只是 API 或静态渲染：

1. 从 Goal 一级导航进入 Workbench，默认看到 Office 式资产库。
2. 最近使用和全部资产网格能打开 Document、Form、Page 和 File。
3. 搜索、类型、来源、状态和排序可组合使用；返回详情前位置得到恢复。
4. 一个包含多个产物的 accepted Result 被拆为多个候选资产。
5. Inbox 展示 AI 的目标资产建议、理由、变化摘要和置信度，但不自动执行。
6. 用户可以新建资产、改选现有资产、拒绝入库，并完成类型化差异审查。
7. 文档直接编辑只保存草稿，明确提交后才产生新版本。
8. Form 填写创建绑定具体 Form 版本的 Submission，不改写 Form 定义。
9. Form 设计修改通过草稿提交新版本。
10. Page 运行前显示风险警告，并验证生成页面不能读取 Chrona 同源状态。
11. AI 修改创建绑定固定资产版本的真实 Task，结果回到 Inbox 后由用户确认。
12. 并发版本变化触发冲突处理，不能最后写入覆盖。
13. 恢复历史版本创建新版本，旧历史仍可查看。
14. 下载源文件和导出消费格式的语义、文件名和版本标识清楚。
15. 预览、导出或 AI Task 失败不会阻断已有资产使用，并提供真实恢复动作。
16. 归档后资产可恢复，来源 Result、Artifact、证据和版本历史不丢失。
17. 桌面 `1440×900`、平板 `1024×768` 和移动 `390×844` 无页面级横向滚动。
18. 移动端能浏览、下载、填写表单和运行页面；不支持的复杂编辑明确说明原因和下一步。
19. 所有卡片悬停操作可通过键盘和移动端菜单访问，焦点顺序、名称和错误提示可理解。
20. Workbench 不复制 Task 生命周期、不隐藏 WaitingForInput/WaitingForApproval 差异，也不获得 Goal 生命周期权威。
21. 新建 Goal Task 自动捕获全部当前正式资产的有界元数据，不出现手动资产选择器。
22. Agent 仅按相关性读取正文，精确读取始终使用 Task 捕获版本。
23. 发布、归档、Retry 和 Replan 不改变既有 Task 快照；Draft 只在发布后影响新 Task。
24. Task Workspace 显示捕获/读取数量，Result 与资产详情只读展示成功读取的安全溯源。

## 16. 与当前实现的关系

本文定义的首版范围现已实现：Goal 一级 Workbench、正式资产库与 Inbox、
accepted Result 自动候选拆分、GoalAsset 正式版本与草稿、乐观冲突、恢复与归档、
Document/Form/Page/File 类型化使用路径、版本绑定 Submission、导出任务、隔离 Page
运行，以及绑定固定资产版本的有界 AI 修改 Task。AI 修改产生的 accepted Result
重新进入 Inbox，由用户确认后才成为正式版本。

实现继续保持以下架构边界：

- accepted Result 和 Artifact 不可变；
- GoalAsset 版本是持续使用层，不回写历史结果；
- AI 修改和外部副作用通过有界 Task；
- Task 使用冻结的资产版本快照；
- 数据模型与迁移遵守当前 release-line migration policy；
- Page iframe 不启用 `allow-same-origin`，不暴露 Chrona 访问密钥、Run token、
  provider 请求或宿主权限；
- 不支持的导出格式显式拒绝，不用伪成功占位替代转换器。
