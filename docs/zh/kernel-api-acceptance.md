# Kernel API 消费者验收与冻结门槛

2026-11-11。当前六命名空间 API 仍为 **UNFROZEN**，目标规范见 [kernel-api-design.md](kernel-api-design.md)。这一页记录可重复的消费者验收及尚不能据此作出的承诺。

## 可运行消费者

`scripts/acceptance/kernel-api-consumer.ts` 只依赖 Node assert；不导入 engine、DB、合同生成器或实现 schema。输入只有 request、loseReply、restart、已安装目标身份。不同宿主可以提供同样的适配器运行这些断言。

`apps/server/src/kernel-api-consumer.bun.test.ts` 为当前实现提供适配器：全新临时数据库、两个真实 SDK 应用、真实 HTTP listener、认证、当前显式 owner 和仅声明 wildcard 的普通应用。夹具安装阶段使用数据库；**消费者断言不查询数据库**。重启关闭宿主并重新连接同一临时数据库，随后查询原 key。

覆盖：

- HTTP 未认证拒绝；普通应用的 wildcard 不赋予 owner 权力。
- 模块分页连续性、跨合同 cursor 拒绝、未知旧接口拒绝、设置输入校验。
- 精确 moduleId 工具调用、同 key 同输入重读、同 key 异输入冲突。
- 工具效果完成后 listener 注入 HTTP 502，不交付业务结果；消费者查询原 callStatus，再使用原 key 调用，效果计数仍为 1。
- 同数据重启后原 callStatus 及原结果仍可读，不重新产生工具效果。
- 应用自己的 timer 登记、其他调用方不可见、重启保留、显式取消。
- 合成凭据设置、列表不泄露值、普通应用不得管理或读取未声明凭据、删除。
- 暂停应用要求固定 key；原生命周期回执可读，同 key 改原因冲突，同数据再次重启后仍可查。

运行 `bun run test:api`，或给 `DATABASE_URL` 和 `CHRONA_DATA_DIR` 指定全新临时目录后单跑该文件。不得让直接测试导入默认真实数据库。首次 fixture 尝试复用已停止的 supervisor 返回 404；最终适配器重新连接 DB，符合重建宿主的前提。

## 分层证据

| 层 | 已有证据 | 不证明什么 |
| --- | --- | --- |
| 声明及参数 | 严格输入输出合同、35 个公开工具的当前内部测试 | 不证明独立实现等价 |
| 内部恢复与事务 | kernel-api、timers、module-migration、agent-recovery、预算定向测试 | 不代替真实传输或掉电测试 |
| 外部消费 | 本页 HTTP/SDK 消费者及同数据宿主重启 | 不覆盖 35 个工具全部错误路径 |
| 产品页面 | 当前渲染器真实浏览器三尺寸 | 夹具数据不能证明实际持续使用 |

## 冻结准入

冻结必须逐项记录通过证据，不能以测试总量抵扣：

1. 为所有公开工具固定输入、输出、错误码、分页及身份语义；包含 secrets 的脱敏、审批的精确动作、模块生命周期的状态和完成含义。
2. 扩展消费者验收到异步生命周期、审批失效、删除与迁移、取消、投递不确定和升级绑定失效；目前这些主要由内部测试覆盖。
3. 故障注入覆盖“写入前、已提交丢回复、实际效果后丢回复、宿主重启”，证明固定回执和禁止未知重放。
4. 对 schema/行为变更明确版本边界和迁移支持矩阵；fresh-data 产品不得承诺旧库可直接升级。
5. 实际运行从发现合同到受控执行、报告、暂停/结束的用户旅程，保存可复查证据。

第二个内核实现不是当前前置条件；消费者独立也不是可替换性已获证明。以上未全部满足前维持 UNFROZEN。
