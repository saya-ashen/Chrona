# P5 规格（第一部分）：幂等键

状态：已实现（2026-10-21）。背景见 [platform-upgrade-plan](platform-upgrade-plan.md) P5 与 [P4 构建通道端到端记录](platform-e2e-p4-build-2026-10-21.md) 发现 3。
本文件是 P5 第一部分的契约；P5 其余项（独立模型审查、按主机放行网络、结晶率）另写。

## 1. 问题

effect 的 `key` 是幂等键。模型写出的模块常把它写成常量，后续不同事件的通知会被当作重复丢弃；模块自带测试通常覆盖不到。

## 2. 入站触发：按条目隔离（执行器）

入站触发执行 effects 时，去重键为 `inbound:<inboundItemId>:<key>`（通知与 `wake_provider` 相同），ModuleRun `executed` 记录该键。同一条目的重复处理仍去重；不同邮件不再互相去重。
定时触发与模块工具保持原键（跨触发去重是有意的用法，如"每天只提醒一次"、同参数工具调用）。

## 3. 定时触发：变形检查（构建）

测试通过后，在一个新的空数据目录中，以清单第一个定时触发器、`now` 与 `now + 1 天` 依次运行入口两次（离线、同一数据目录）。

- 两次都有 effects，且有相同的 `type:key` → `report.keyProbe = { status: "repeated", keys }`；审批卡片显示警告；不自动启用。不拒绝：模块可能有意只通知一次。
- 两次 key 都不同 → `passed`，卡片显示一行通过。
- 无定时触发、入口失败、输出无效或任一次没有 effects → 不记录、不显示（检查没有结论）。

## 4. 冒烟运行（构建）

测试与连续性通过后，Chrona 以清单第一个定时触发器（`firedAt = now`）和第一个入站触发器（合成条目 `smoke@chrona.invalid`）各在新的空数据目录中离线运行入口一次。任一次退出码非 0 或 stdout 不是合法模块输出 → 版本拒绝，`report.errors` 记公开原因（截断的 stderr / stdout），与清单错误一样进入 Provider 修复唤醒或构建通道的下一次尝试。模块工具不调用（参数无法合成）。

原因：模块自带测试可能根本不执行入口（真实运行中见过只 grep 源码的测试）；冒烟运行不判断测试质量，只保证入口能跑、输出合规。
