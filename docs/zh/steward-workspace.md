# 工作区模型：Provider 办事，Chrona 补足它做不到的

状态：2026-10-15 用户确认方向，取代 [steward-rebuild](steward-rebuild.md) 中的数据模型、Agent 角色与页面结构
（其清理范围与部署结论仍有效）。目标依据仍是 [steward-goals](steward-goals.md)。

## 1. 为什么改

第一版把内容格式和 Agent 的能力都固定死了：Agent 只能“发布不可变成果版本”，所以每次整篇重写；
接待与事务 Agent 两个角色各说各的；问题、审批、建议、照看、跟进各有专用类型；
还在 Chrona 里重造了联网预检、脚本沙箱等 Provider 本来就有的能力。
真实对话（10 天雅思备考规划）暴露了：规划无法协作修改、无法拆分执行、材料只能塞进正文、过时追问、模板化通知。

原则：
- **AI = Provider**（Pi、Claude Code、Codex……），自带文件读写、命令、联网、沙箱、会话。Chrona 不重复提供这些能力。
- **Provider 决定怎么组织和推进事情。** 系统不预设“方案 / 任务 / 成果 / 问题”类型。
- **Chrona 只提供 Provider 做不到的能力**，并守住少数底线。

## 2. 分工

| Provider 自带（Chrona 不提供） | Chrona 提供（Provider 做不到） |
| --- | --- |
| 读写 / 局部编辑文件、执行命令、联网检索与抓取、脚本与沙箱、子 Agent、会话内上下文 | **调度器**：一次 / 周期唤醒，时区感知，持久化，重启补跑 |
| 自己的权限与工具配置（由 Chrona 启动时按设置传入） | **触发与排队**：聊天消息、来源事件、用户在网页的编辑 / 勾选、定时到点 → 唤醒对应事务；前台 / 后台两条通道；运行中到达的消息注入当前运行（借助 Provider 的机制） |
| | **持久化**：事务目录（文件）+ git 历史（差异、撤回）、聊天记录、长期偏好、会话 id |
| | **送达**：QQ / 网页消息、重试、打扰预算（日上限、安静时段、汇总） |
| | **外部接入与凭据**：来源轮询 / webhook；QQ 等凭据只在 Chrona，Provider 不可见 |
| | **权限闸门与审计**：Chrona 掌握的对外通道（给别人发消息、来源写操作等）按授权；所有 Chrona 工具调用留痕 |
| | **资源边界与恢复**：单次运行时长、每日运行上限、租约、崩溃恢复 |
| | **文件进出**：用户上传的图片 / PDF 放进事务目录；生成的文件可下载 |
| | **呈现**：渲染事务目录（Markdown、复选框、面板块），把用户编辑写回文件并唤醒 Provider |

## 3. 事务 = 一个目录

```text
data/affairs/<affair-id>/          ← Provider 的工作目录（git 仓库）
  README.md                        ← 总览页（二级页面；第一段作为摘要的后备）
  任意子目录与 .md 文件              ← Provider 自己决定：日页面、材料、笔记……
  *.csv / *.json                   ← 面板数据等（面板块在 Markdown 里引用）
  .chrona/                         ← Chrona 的元数据（Provider 可读，不应修改）
  *.ui.json                        ← AI 拼装的页面（json-render 规格，见 §7.1）
  .chrona/entry                    ← 入口页路径（由 chrona_ui_set 维护）
```

- 每次运行结束、用户在网页上编辑后，Chrona 自动 `git commit`（作者：Provider 名 / 用户），提供差异与撤回。
- Markdown 约定（仅渲染约定，不是结构约束）：`- [ ]` 复选框可在网页勾选；```` ```chrona-panel ```` 块声明字段与数据文件，网页渲染为表单 + 表格 + 趋势。

## 4. Chrona 工具（经 MCP 暴露给所有 Provider；Pi 用现有扩展桥接到同一接口）

| 工具 | 作用 |
| --- | --- |
| `reply` | 在当前对话里回复用户（前台运行）；可附带改过的页面路径 |
| `notify` | 主动推送（后台运行），经打扰预算 |
| `schedule` / `schedule_list` / `schedule_cancel` | 一次 / 周期唤醒；`wake`（叫醒 Provider 并带上给未来自己的指令）或 `remind`（到点直接把固定文本发给用户，不调模型） |
| `affairs` / `affair_create` / `affair_update` | 列出事务、新建（建目录）、改标题 / 状态（进行中 / 暂停 / 结束） |
| `request_approval` | 需要用户批准的、经 Chrona 通道的对外动作 |
| `remember` / `forget` | 长期偏好 |
| `read_source` | 读取 Chrona 接入的来源事件 |
| `panel_add_entry` | 可选：向面板数据文件追加一行（Provider 也可直接写文件） |

## 5. 运行

- **前台运行**（有人说话）：Chrona 选定 Provider，工作目录为相关事务目录（不确定时为工作区根目录，可看到所有事务的 README 摘要），
  带上最近对话、偏好与当前时间。Provider 回复、改文件、建调度。长任务用 `schedule(at=now)` 转后台，并在回复里说清楚。
- **后台运行**（调度到点、来源事件、用户编辑）：在该事务目录中工作，必要时 `notify`。
- 运行中收到新消息：通过 Provider 的机制注入（Pi follow-up 消息；Claude Code 流式输入），不另起运行。
- 会话：每件事务记录 Provider 会话 id，下次运行优先恢复会话；会话丢失时靠目录内容与动态记录重建上下文。
- Provider 适配器接口：`start(run)` 返回 `inject(message)`、`abort()` 与 `done`，另有 `health()`；安全进度、用量、资源与阻塞交互经运行回调交给 Chrona。先做 Pi，再做其他 Provider。
- 当前 Pi 宿主接线：全局待答复入口、运行绑定/过期/中断失效、安全进度与用量、显式资源清单及可靠停止，见 [Provider 运行说明](provider-runtime.md)。这是转译 Provider 原生协议，不是新的执行/权限引擎；原生交互不授予 Chrona Grant。

## 6. 数据模型（数据库只存 Provider 做不到的部分）

| 模型 | 说明 |
| --- | --- |
| `Affair` | id、标题、状态、目录路径、Provider 会话 id、最近活动 |
| `Schedule` | 所属事务、规则（at / daily / weekly / every）、模式（wake / remind）、内容、下次时间、状态 |
| `Run` | 通道、触发原因、Provider、开始 / 结束、结局、Chrona 工具调用记录 |
| `Message` | 聊天记录（入 / 出），可关联事务 |
| `Activity` | 事务动态（谁做了什么、改了哪些文件、对应 commit） |
| `Approval` | 需要批准的对外动作 |
| `Grant` / `Preference` / `Notification` / `SourceConnection` / `InboundEvent` / `Audit` | 沿用 |

删除：`AffairResult`、`Ask`（question / suggestion）、照看字段、`FollowUp`、`ManagedTool` / `ToolVersion` / `ToolRun`、
`PanelEntry`（改为文件）、Chrona 的网页预检与脚本沙箱、接待 / 事务两角色。

## 7. 网页

视觉标准：[原型](../prototypes/steward-pages.html) 与 `DESIGN.md`。

- **今日**：一句话概括；等你决定；每件进行中的事务一张卡片（Provider 拼装的今日卡片；没有时为现状一句话、最近一条进展、下一次）；临近安排。
- **事务列表**：标题、状态、现状一句话、下一次、最近更新。
- **事务**：打开即是 Provider 拼装的**入口页**（§7.1；没有时为 README）。其余文件是二级页面：从入口页的链接或“页面、安排与经过”进入，
  在独立的阅读视图中渲染（可编辑、可勾选、面板块可填写），带“← 返回首页”。对话与修订历史（差异 / 撤回）、技术详情也是二级页面。
- **设置**：聊天、通知、授权、偏好、来源、Provider（选择与健康状态）、运行状况。

### 7.1 页面由 AI 拼装（生成式界面）

页面怎么排、首页放什么，由 Provider 在运行时决定；Chrona 不规定版式，只提供**积木、规则和偏好**。

- **积木**：组件目录（[json-render](https://github.com/vercel-labs/json-render)，`packages/ui-catalog`）。
  通用组件取自 `@json-render/shadcn`（卡片、布局、标题、文本、徽标、提示、进度、表格、标签页、折叠、输入、选择、按钮……），
  另加绑定事务文件的 Chrona 组件：`TaskList`（取某页某标题下的 `- [ ]` 项，勾选写回该页）、`PageLink`（二级页面）、`Upload`（上传到指定目录并告诉 Chrona）。
  动作是封闭集合，映射到 Chrona 已有能力：`say`（以用户身份就此事务发一句话）、`open`（打开页面）；不允许任意脚本。
- **页面文件**：`*.ui.json`（json-render 规格：`root` + `elements` + `state`），与 Markdown 页并列放在事务目录、随 git 提交。
  Provider 用 `chrona_ui_set` 写入：Chrona 立即按目录校验并返回问题；可指定为本事务的**入口页**（打开事务时显示）或**今日卡片**（今日页上代表此事务）。
  没有入口页时退回 README。
- **规则**：`chrona_ui_guide` 返回组件说明、界面规则与学到的界面偏好；规则的默认原则是 §10 的“最小入口”：
  首页只放现在需要用户处理、能就地完成的事，计划 / 材料 / 方法 / 历史放二级页面；一区一个主要操作；不写声明套话；勾选项用 `TaskList` 指向页面，不复制文字；只用事务的真实内容。
- **偏好学习**：每个拼装页面带“这页不好用 / 提意见”入口，意见连同页面路径作为关联此事务的消息交给 Provider（改页面，并用 `chrona_remember` 以 `topic: "ui"` 记下稳定偏好）。
  Chrona 记录使用信号（打开了哪些页面、用过哪些动作、哪些清单一直没动），`chrona_ui_guide` 附上近期摘要，供 Provider 调整。
- 安全：未在目录中的组件与动作不渲染、不执行；已结束的事务只读；页面内容只是展示数据，不能授予权限。

## 8. 验收

以 10 天雅思备考对话为第一个场景（逐字重放用户消息）：
1. 规划在文件里逐步成形，每次局部修改，聊天里说清改了什么；
2. 回答后不再出现过时追问；
3. 每日日程拆成可勾选的日页面，提醒按约定时间到达 QQ；
4. “准备第一天材料”生成挂在第 1 天下的材料页，不改写主页；
5. 第二天早上调度准时唤醒，准备当天材料并提醒。
6. **每天照着做**：打开事务即看到今天要做的几项与进度；勾选、上传录音、回答问题都在首页完成；
   做完后首页切到下一步，计划等长内容只在二级页面。手机上首屏能看到“今天要做”。
另用 3 个未写进任务书的新需求轮换验收；换用 Claude Code 作为 Provider 重跑场景 1–3。

## 9. 使用场景与所需能力（思维实验，2026-10-15）

| 场景 | Provider 负责 | Chrona 必须补的 |
| --- | --- | --- |
| 邮箱 / Telegram 消息处理并汇总推送 | 判断、归类、摘要、起草回复 | 连接器（凭据、增量同步、去重）、入站落成文件、批处理与防抖、AI 写 Chrona 执行的廉价规则、定时汇总、代发需批准、隐私开关 |
| 10 天备考规划 | 规划、日页面、材料 | 调度、聊天附件进出、“今天做完了”映射到勾选 |
| 盯服务 / 价格 / 版本 | 写检查脚本、解读变化 | 定时确定性任务（沙箱跑脚本，有变化才叫醒） |
| 服务器故障诊断 | 自己 SSH、查、提方案 | Pi 的受支持 UI 请求可转给用户，受本次运行时限约束；跨日原生权限会话/其他 Provider 中继未完成 |
| 账单 / 记账 | 识别、记录、汇总 | 附件入站、面板数据文件、到期提醒、隐私与保留期 |
| 稍后读 | 读、摘要 | 聊天入站链接归档、调度、汇总 |
| 求职季 | 搜索、文书 | 截止日提醒、日历出口（ICS）— 之后 |
| 约人 / 协调他人 | 起草 | 代发审批；分享与外部参与者 — 之后 |
| 习惯打卡 | 解读、周报 | 定时询问、聊天快捷回复记入面板 |
| 多渠道推送 | — | 按紧急程度选择渠道 — 之后 |
| 额度用完 / Provider 故障 | — | 排队补跑、如实告知、成本预算、备用 Provider（第二个 Provider 后） |
| 引用某条通知回复 | 理解反馈 | 引用消息 → 事务 / 页面映射 |

## 10. 第一版范围（只接 Pi）

做：调度器、触发排队与运行中注入（Pi RPC）、事务目录 + git 历史 + 网页渲染编辑、送达与打扰预算 / 汇总、
连接器框架 + **邮箱（IMAP 只读同步，SMTP 代发需批准）**、批处理与廉价规则、定时确定性任务、
Chrona 通道对外动作的审批、聊天附件与引用映射、成本与运行上限。
暂不做：Claude Code / 第二个 Provider、通用/跨日 Provider 权限会话恢复、Telegram、多渠道送达、日历出口、分享。Pi 的受支持阻塞 UI 请求已有有界桥接，不意味着任意 Provider 的私有权限协议均已接通。

运行环境：Pi 进程整体运行在 bubblewrap 中（事务目录可写、可联网、其余只读）；没有 bwrap 时关闭 bash，只保留文件与网页工具。
Chino 部署需在包装中加入 bubblewrap 与 git。
