# v2-27：可信本地执行与可靠演化

状态：P0、P1a 与 P1b 已本地验证；P1b 已通过独立复核及浏览器 fixture 验收，尚未部署。P1b 基线为 579 通过、1 跳过，浏览器 fixture 40/40。P2 已实现并验证：工具参数支持有界递归的对象／数组、运行时严格校验和原生 JSON 传递；manifest 元数据复用于 reference、overview、Provider catalog 与 owner MCP 工具发现；构建前校验声明的示例。遗留标量接口语义不变。P2 的测试结果与未通过的旧部署 fixture 检查见 §7。未修改实际服务配置或现有授权，未部署、未提交、未调用真实模型。

## 1. 定位与适用范围

Chrona 是用户与 Agent 共用的、可随需求演化的本地超级软件工具。用户直接使用应用，Agent 经同一套公开功能接口使用应用；AI 或用户根据实际需要决定新增或修改模块，也可以在用户授权范围内自主推进演化。

模块是软件功能的组织与演化单位，不是每段经验的归宿。学习、记忆、一次性执行与构建模块没有强制转换关系；本次不新增 skills 系统，也不重建 Provider 已有的执行能力。

主要部署假设是单一 owner 信任自己的本地 Agent 和启用的模块，不默认采用运行陌生人代码的多租户云平台威胁模型。信任本地执行不等于承诺代码没有错误。

本方向仅适用于 Chrona。agent-growth-lab 的候选程序仍须与评估器、预算和隐藏评估隔离，以维护实验有效性；不得因本文取消其隔离要求。

## 2. P0：执行环境与用户授权解耦

### 当前基线

- `script-sandbox.ts` 已支持 bwrap 隔离与普通本地子进程。
- 旧/未配置执行模式下，`approval-level.ts` 将未隔离模块版本判为红色；可信本地模式只解除这一项风险，不解除迁移、入口模块/新增权限、凭据外泄风险。
- 更新启用策略已按 §3 简化：构建检查通过即自动启用，不再要求长期模块启用授权；启动前自动代码回滚见 §5。

本阶段已解除“允许本地执行，却仅因未隔离阻断已授权更新”的矛盾，不引入新的多后端框架。

### 目标

- 可信本地执行成为正式支持、经 owner 明确选择的模式，而非沙箱失败后的隐式降级。
- 执行环境与演化授权分开：机器是否安装 bwrap，不决定用户是否允许自动更新。
- 用户选择可信本地执行后，不再仅因 `!isolated` 将每次更新判红；已授权范围内的更新可在检查通过后自动启用。
- 用户明确要求隔离时，隔离不可用必须停止相关执行并说明原因，不静默回退本地。
- 复用当前本地与 bwrap 路径；不迁移到 microVM，不新增容器平台或通用后端抽象。
- 配置为 `CHRONA_STEWARD_EXECUTION_MODE=trusted-local` 时，模块、构建检查和 Provider 明确本地执行，即使已安装 bwrap 也不包装隔离。
- 配置为 `CHRONA_STEWARD_EXECUTION_MODE=required-isolation` 时，模块与 Provider 仅在 bwrap 可用且隔离探测成功后执行；否则失败关闭，不回退本地。
- 当前依赖安装器仍是宿主执行，Python 构建后端可能执行包代码。因此该模式下，提交含 `package.json`、`pyproject.toml` 或系统 `packages` 的候选会在安装前拒绝；无依赖候选可继续隔离检查。尚未实现隔离依赖安装，不能通过自动降级绕过此限制。可信本地与旧配置的依赖安装行为不变。
- 未设置或为空时默认 `trusted-local`，模块、构建检查和 Provider 本地执行，即使已安装 bwrap 也不包装隔离；未知非空值拒绝启动。
- 模式由服务 owner 环境配置控制，不由模块或 Provider 请求选择。隔离本身不能替代本地执行边界说明。
- 执行模式不授予运行时对外动作权限。检查失败时不会自动激活；数据迁移、新增凭据等仍按 §3 请求用户决定。

### 真实边界

本地进程拥有操作系统用户授予的权限。清单、路由和审批约束正常调用路径，提供协作协议、误操作防护和追溯，但不能阻止同用户恶意代码绕过接口读取文件或修改控制面。因此：

- 不声称清单是本地模块全部 OS 权限，也不声称平台目录对同用户代码不可访问。
- 保留“Agent 不应直接修改内核、授权策略与正式状态”的产品规则；它是受信执行约定，不冒充 OS 强隔离。
- 保留凭据最小暴露和脱敏，不把它描述为对任意本地代码的秘密隔离保证。

## 3. P0：围绕实际变化简化审批

复用现有策略、授权与审批，不建立第二套系统。

| 变化 | 目标行为 |
|---|---|
| 已授权范围内的修复、界面修改、实现优化 | 类型、测试、启动等必要检查通过后可自动更新，事后说明变化 |
| 新建功能 | 根据用户是否明确授权自主新增功能决定；不能由模型自行授予权限 |
| 扩大真实数据访问、增加外部账户操作 | 请求新增授权，展示实际影响 |
| 删除数据、不可逆迁移、恢复旧数据 | 明确说明数据影响并确认，不能用代码回滚承诺掩盖数据损失 |
| 修改授权规则 | 独立、明确的用户决定 |

清单差异继续用于解释依赖、接口和影响，但不能把所有内部声明变动等同于实际权限扩大。入口功能、真实外部动作等具体分级在实施时逐项核对，不笼统取消现有保护。

更新审批策略已由 [security-simplification.md §3.1](../security-simplification.md) 取代：构建检查全部通过即自动启用并事后通知；迁移已有数据、新增凭据与删除应用才问用户。不再使用 AI 复核、审批分级或长期模块启用授权。

## 4. P1：完成应用接口契约

保留模块边界和 `chrona.call`。其作用不仅是准入控制，更是稳定组合功能、定位错误和独立替换实现。

优先完成 [v2-25 第 3 步](platform-v2-25-contracts.md)：

1. 应用工具声明返回结构。
2. 从同一契约生成工具参考与 TypeScript 类型。
3. 路由定位返回结构不符的被调用模块。
4. 接口更新列出依赖调用方，形成影响清单。

不重复实现已有系统工具契约和构建类型检查，不建立独立的文档类型系统。接口变化先做有限影响分析，不增加复杂 schema 兼容性推理引擎。

## 5. P1：从构建成功到更新后可用

复用版本、检查、快照、迁移、回滚、supervisor 和[故障恢复](../module-recovery.md)，不重建发布系统。

- **更新前**：根据已声明的调用关系与接口差异，列出受影响应用并运行可用的相关检查；不能把只测试候选自身称为验证全部依赖。
- **更新后**：区分已构建、已激活、已验证可用；进程启动或 socket 重连不等于功能恢复。
- **无副作用验证**：使用明确安全的自检或真实成功调用作为证据，不为健康检查发送消息、交易或修改用户数据。
- **有限自动恢复**：新激活版本在任何事件投递前启动失败时，自动尝试一次切回前一已批准版本，无需用户开启或长期授权，入口/监听、含凭据和 network 模块同样适用。候选与目标须均已批准、manifest 有效且数据 schema 与当前数据一致；动态/变化日程、迁移/恢复、分组激活、已验证能力或非 active/激活身份与 hash 已变化等情况均拒绝自动回滚。不恢复旧数据、不重建日程、不重放工作；恢复目标不会自动继续回滚，避免版本来回切换。
- **结果未知**：外部操作结果未知时不自动重放；恢复代码不会撤销已发生的外部效果。
- **有界修复**：同一故障的修复尝试与模型费用须受已有预算约束；不新增无限循环或常驻修复 Agent。具体次数在实施时确定。

复用构建会话、应用页与 activity 展示一次变更：修改了什么、验证了什么、是否生效、影响哪些应用、如何恢复。Agent 获得对应结构化结果，不能靠自然语言猜测完成状态。失败明确说明旧版本是否仍可用、数据是否改变以及下一步。

## 6. P2：结构化参数与功能自描述

### 结构化参数

应用工具的 `parameters` 支持递归 `string`（可列举 enum）、`number`、`boolean`、`array` 和 `object`。对象默认 `required: []`、`additionalProperties: false`；显式放开的对象仍受 JSON 输入边界约束。递归 schema 限制为最多 1000 个节点、深度 24。运行时校验拒绝 null、错误嵌套类型、枚举外值、非有限数字、缺少必填字段和闭合对象的未知字段；错误只暴露有限的脱敏字段路径与校验码。数组／对象保持原生 JSON 值穿过 manifest、事件、SDK、Provider 与 owner MCP，不将 JSON 字符串猜测解析成对象。旧字符串参数与工具行为不变。

### 功能自描述

现有 `reference`、`overview`、Provider catalog 与 owner MCP `modules.tools` 使用活动 manifest 同一份参数、输出和描述性元数据；不新增插件商店或能力注册中心。工具可以声明最多 3 个调用示例、8 个副作用说明和 8 个常见错误／恢复方法；构建阶段用同一输入、输出契约检查示例，不执行工具。未声明元数据显示为未提供（null），不推断“无副作用”。

`idempotent` 仍是唯一既有重试权限；展示的重试说明直接由该标记推导，不新增自动重试。可见工具列表按 audience 与 visibility 筛选；模块可调用 `modules` 工具，`uses: ["*"]` 额外到达 `owner` 工具，其他 `uses` 仅作契约（[安全机制简化 §3.2](../security-simplification.md)）；自描述信息不改变受众。迁移示例：新工具可接收 `{ filters: [{ state: "open" }] }` 这样的原生值；旧工具若声明 `query: string`，`{"query":"{\"state\":\"open\"}"}` 仍是字符串，不会自动转成对象。

## 8. 不做与保留

不做：microVM 全面迁移、每模块 VM、新工作流/DAG、第二套审批、全模块凭据代理、重新实现 Provider 技能系统、自动放宽现有授权。

保留：版本与 hash、模块路由、必要输入输出校验、测试和启动检查、数据迁移备份、停止能力、资源与模型预算、可追溯结果及独立救援入口。

安全隔离可以按本地信任模型简化；保障软件升级质量与数据恢复的机制不能因此一起删除。
