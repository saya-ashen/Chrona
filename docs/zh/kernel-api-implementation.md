# 内核 API 实施记录

状态：2026-11-11 已调整实现、SDK 和维护中的调用方，完成下述离线验证；**未冻结、未部署**。依据：[公开 API 规范](kernel-api-design.md)。验证基于 `fbc4464a` 之后的未提交工作区；没有自动提交或覆盖原有未提交改动。

## 实现范围

- 六个命名空间、35 个工具；应用通过 `{moduleId, tool}` 调用。合并发现与诊断，删除旧公开名称。
- 结构化内核参数、必须声明的输出、统一分页、八个错误码及有限恢复原因。key 位于调用选项，原样交给处理器；持久记录拒绝同 key 不同请求。
- `callStatus` 支持原目标和 key 查询；普通 `null` 与未留存的私密结果区分。凭据、Agent 正文和有限事实不复制到通用调用账本。
- `authority: "owner"` 检查实际批准版本，`uses` 不授予权限；提高权限仍需精确激活审批，预装无例外。旧 `tools[].callers` 字段严格拒绝。
- 生命周期复用调用账本；`callStatus` 与 `modules.operation` 分别回答调用返回和动作后置条件。健康摘要保留 `stopping / unknown`，不将配置暂停伪装为进程退出证明。
- `timers` 提供持久单次与周期唤醒、版本绑定、预算、过期合并及未知结果。取消/替换不被迟到返回覆盖；预算耗尽应用不阻塞其他应用。
- `activity.usage` 整合模块补全预算记录与 timer 唤醒；单一事实消费者、确认及撤回语义保留。具体计量范围见规范。
- Agent 对话与实验性 `work-*` 合同分离；Web 生命周期按钮使用应用 ID。应用调用方、SDK、生成合同、哈希变更记录及本地发行材料同步调整。

## 审核后修复（2026-11-11）

公开六个命名空间、35 个工具及调用参数保持不变。本轮修复审核中复现的七项问题：

- Timer 在实际发送前提交当前时间的唤醒计量并复查预算，避免慢处理器或连接延迟绕过最小间隔。
- 取消／替换与最终验证、计量提交及同步发送使用同一运行时串行边界；连接期间已取消的旧事件不会发送。暂停且确定尚未发送的事件保留待处理，恢复后再合并触发，不计为实际唤醒。
- 恢复时仅使用绑定应用 ID、批准 hash 和唯一事件 ID 的明确成功运行证据完成账本；确定未发送的延期尝试单独留证，不遮蔽后续成功。无证据或有歧义仍停止为 unknown，不自动重放。结算写入失败后，同一运行时下一轮也会重新核对证据。
- 一旦观察到版本变化，持久化 stale 并清空下次时间；回滚到原 hash 也必须重新 set。
- 生命周期原始调用 output 保持固定；当前操作状态单独存于 operationOutput。审批回滚的成功状态随激活事务一起提交，可跨重启、后续停用和版本变化保留。
- 辅助 ModuleCall 日志写入失败只产生不含参数／输出的诊断，不能把已成功的写入改报失败，也不能阻断异步交付。
- 异步系统工具执行后发现输出不符合合同，继续报告 unknown，并保留公开错误分类；不伪装为确定失败。

另修正两处仍断言旧私密留存形式的测试，拆清复杂度超限函数职责；没有禁用 lint 规则或改低基线。初始迁移增加独立操作状态字段，仍仅支持全新开发数据。

## 未覆盖与使用限制

- 初始 schema 已同步，只支持全新开发数据目录。既有数据库 checksum 拒绝守卫保留，未提供或执行旧库迁移。
- 没有更新现有服务、生产数据库或真实账号；未验证真实模型端到端、持续使用、其他操作系统或跨语言替代内核。
- `work-*` 仍为实验接口。API 冻结和生产可用不能由本记录自动推定。
