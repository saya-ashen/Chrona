# 编码工作台

2026-11-08 后续范围确认：首版是直接修改外部项目的普通 coding agent 入口；完成后可在同一会话继续，不以 diff 审查或成果接受作为写入条件。操作 Chrona 所在机器，由页面添加已有目录，必须支持非 Git、空目录和尚无首次提交的仓库。下文早期 W1 的验收按钮不再是普通编码主流程；最终范围与难点见[实现评估](coding-workbench-implementation-assessment.md)。

Web 导航中的「编码工作台」（`/p/coding/main`）提供基本的服务器编码操作。页面由 coding 应用登记，所有操作通过 coding 工具调用 Agent；业务状态和成果仍由 coding 管理。

## 使用

1. 先配置并授权服务器项目及执行位置。页面只列出在线的服务器项目；无可用项目时显示配置提示并禁用开始按钮。
2. 选择项目、填写工作目标，点击「开始工作」。默认预算为 10 分钟、30 次工具调用。
3. 从「已有工作」选择并打开工作，查看回复、进度、待答复问题与成果。当前工作每 5 秒刷新。
4. 执行期间可发送补充要求、回答问题，或请求停止。确认问题填写「是」或「否」，选择问题填写完整选项。
5. 执行停止后核对最终回复、最新成果代码差异及成果引用，再接受所选成果。接受只记录验收，不会提交、合并代码或删除工作目录。

请求停止后，页面会区分「尚未确认」和「执行已停止」。停止待确认时不要自行重跑或清理目录。创建和控制操作保留请求标识，重试不会主动重新启动同一工作。

## 当前范围

这是基础版本，支持既有单服务器工作的创建、切换、查看、控制与成果验收。多位置工作、父子工作图、完整文件编辑器与终端不在此页面的范围内。它不是完整 Orca 界面的复刻。

进度显示最多前 100 条事件，并在缺失或省略时给出提示；最终回复和最新成果差异单独显示。页面没有逐 token 的输出流。已有工作列表最多读取 100 项。

## 验证

使用受控 Agent 响应检查创建重试、原始请求冲突、执行引用归属、补充要求、问题答复、停止证据、成果差异和验收；通过实际 SDK 作者测试与受检安装验证。浏览器在桌面、平板和手机尺寸检查空状态与模拟详情，并验证五类操作的请求。验证没有调用真实模型，也没有对真实项目执行编码工作。


## 下一阶段：先交付可日常使用的工作台

2026-11-08 用户调整优先级：先交付日常可用的编码页面，通用调用上下文、Run 和产出协议放在之后；随后明确开发前先调研，不能把复杂的 Orca 界面作为默认目标。上文描述已实现的基础页，本节是待开发范围；全项目顺序以[统一路线](development-roadmap.md)为准，交互参考与取舍见[项目调研](workbench-reference-research.md)。

页面布局尚未冻结，撤回“项目/会话/工作列表 + 主对话与进度 + 成果和代码差异”作为固定三栏要求。W0 先比较“会话主区＋按需成果”与“工作收件箱＋详情”，验证待答复、离开返回、停止未确认和成果审查，再确定结构。首个可用版本先服务已授权服务器项目，优先完成选中工作恢复、连续进度、完整回复、自然的补充输入和问答控件、清楚的停止状态，以及成果逐份查看/接受。现有每五秒读取前 100 条事件不能直接作为完整历史，需接事件游标/分页或按现有能力增量读取，并保留缺口提示；不要求首版实现逐 token 推送。

现有能力与具体缺口：

| 能力 | 已有基础 | 下一步 |
| --- | --- | --- |
| 会话与工作 | `coding.sessions`、单项 create/get/list、v2 `coding.work` | 页面接入持久选择；核对 sessions 对 v2 父子工作的绑定和读取，不直接假定全兼容 |
| 执行与进度 | Agent run/get/stream/inspect/write/respond/interrupt；coding 已有映射层 | 通过 coding 提供稳定页面数据与操作，补齐事件接续、回复/附件的完整性展示 |
| 工作树与并行 | v2 work/placement、独立工作树、父子工作与依赖、workspace-cleanup | 后续接入页面；清理仍检查停止/占用及预览确认回执，不自动清理 |
| 成果 | 现有捕获、差异、版本与人工接受 | 改善 diff 阅读和逐份成果操作；接受不冒充代码提交/合并 |
| 多入口 | Web 页面、owner MCP、editor 等共用路由与 coding 工具 | 验证同一业务工作跨入口读写、过期问题拒绝与重启恢复；不复制会话库和执行队列 |
| 页面表现 | 统一 json-render 的布局、表单、Markdown、预格式文本、分页等 | 必要时给 web 增加通用的面板、滚动、差异和事件显示组件；不把 coding 业务逻辑写进 web/内核 |

第一阶段 W1 以单项工作真正可用为目标；W2 再接既有独立工作树、父子工作和多入口。完整编辑器、交互终端、自动合并及通用远端宿主单独评估。未来调用治理改变底层执行引用时，在 coding 的 Agent 适配处迁移，业务会话/工作标识保持独立；不为等待架构重写而推迟页面。

验收覆盖：重复点击/网络重试不重开工作；切换或刷新不丢当前工作；历史分页不丢进度或重复拼接；待答复问题和停止证据真实；成果接受不提交/合并；另一个入口能看到同一工作状态。自动检查用受控执行器，真实项目模型使用单独记录授权和观察结果。
