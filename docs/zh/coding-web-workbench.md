# 编码工作台

2026-11-08：连续编码工作台已完成开发集成。入口是 Web 的「编码工作台」（`/p/coding/main`），页面和业务记录归 coding 应用所有，操作经公开路由调用 projects 与 Agent。实现依据是[范围评估](coding-workbench-implementation-assessment.md)和已认可的[交互原型](../prototypes/coding-workbench/index.html)；验证范围见[开发验证记录](coding-workbench-validation.md)。这些记录不表示已部署或已用真实模型验收。

## 使用

1. 首次打开即可在「默认空间」输入需求，无需注册或选择项目。Chrona 自动准备一个独立工作目录，位于内部数据根目录旁的 `workspaces/<调用身份摘要>`，与数据库、凭据及应用内部数据分开。
2. 全局「新对话」进入默认空间；项目内的「＋ 新建对话」进入该项目。左侧按项目分组列出对话，先打开草稿，发送第一条消息后才保存新对话。
3. 「＋ 添加项目」接受 **Chrona 服务所在机器**上已有目录的绝对路径，添加后立即进入该项目的新对话，不需要重启。普通 Git、带未提交内容的仓库、无首次提交的仓库、非 Git 和已有空目录均可使用；不初始化 Git、不提交或清理文件。
4. 在「默认空间设置」中可改用 home 或其他已有目录。切换默认目录只影响之后的新对话，旧对话继续使用原项目与 Provider 上下文，旧项目引用保留。
5. Agent 直接编辑绑定目录。不同对话具有独立上下文，允许操作同一目录；Chrona 不额外施加跨对话目录锁或排队。执行中可补充要求、回答原生问题或请求停止；每轮默认最多 10 分钟、30 次工具调用。
6. 当前轮完成或确认停止后继续输入，开始使用原 Provider 上下文的新一轮；该对话停止未确认或状态未知时，仍需先核对本轮状态。刷新恢复上次选择的对话或项目草稿，列表按最后一条用户输入排序，后台进度不会改变顺序。
7. 按需查看回复、工具详情、代码差异和执行记录。桌面侧栏可收起；手机默认直接进入输入区，可切换项目列表。

普通编码流程没有强制成果接受，不会因页面显示完成而自动 commit、push、merge 或删除目录。底层成果接受接口仍只保存业务验收记录。

## 连续性与恢复

输入及其目标在分发前保存。同一请求重试核对原操作，不创建另一轮。发送结果不明确时，显示「核对并重试」；确认未被接纳的发送保留失败记录并允许继续。停止请求必须携带原工作引用，旧页面请求不会取消后来的轮次。

同一 Provider 上下文的当前轮次由数据库事务保存的会话头判断，不依赖时间戳和随机编号排序。续接只接受同一实际调用身份、应用版本、项目目录与已确认停止的当前轮次。Provider 会话文件缺失或身份、目录不匹配时明确失败，不悄悄改成无上下文的新会话。

回复与事件游标缓存在 coding 的私有会话数据中。页面增量读事件、去重并分页显示长回复；已缓存内容可在 Agent 暂时不可用时阅读。实际事件缺口、截断或保留过期会显示限制提示，正常首次快照刷新不表示历史缺失。页面仍采用轮询，不承诺逐 token 的实时推送，也不能恢复从未读到且已过期的内容。

## 项目与差异

页面登记项目按工作区、owner 和实际调用应用隔离。登记保留规范目录与物理身份；启动时再次核对，并为本轮读取当前 Git 基线。项目被替换或权限失效时，执行应拒绝或报告冲突，不悄悄换目录。不同普通本机会话共享目录不构成拒绝条件。

新登记项目即时生效。旧静态项目配置继续服务原有执行引用，但不会自动导入页面目录列表；需要显示在新页面时显式添加已有目录。当前不提供项目登记删除或 Git URL 克隆。

代码差异是可选信息。Git 基线比较可能包含已有未提交修改，不能全归因于本轮 Agent。非 Git、无提交或无法可靠比较的目录仍可编码；页面如实显示差异不可用，不将 snapshot 摘要当成备份或可还原快照。每轮捕获文件按 attempt 分开保存，续接不覆盖前一轮证据。

## 当前边界与后续

首版支持本机目录和 v1 连续工作。v2 固定设备、独立 worktree、父子工作图与跨入口完整对话接续尚未接到此页；现有底层接口不等于这些页面场景已验收。完整编辑器、交互终端和通用远端宿主不在首版范围。

页面继续使用共享 json-render。web 提供通用 Workspace、ScrollArea、Message、CodeDiff、ActionOption 和表单组件，coding 管理项目选择、会话、回复与业务动作；没有另建执行队列或直接连接 Pi。问题卡片和输入区现在通过 `web.page-set` 的应用私有组合定义登记，Web 提供明确的 submit 与 statusTone 契约；全站外壳统一管理主题与导航，详见[Web 外壳与应用组合组件](web-components-and-shell.md)。

下一步先在明确授权的隔离项目中验证真实模型的两轮直接编辑、问题答复、完成/停止与离开返回，再据观察修复产品阻塞。全项目后续顺序以[开发路线](development-roadmap.md)为准；通用调用上下文与 Run 改造不是此页的前置条件。
