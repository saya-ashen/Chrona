## 创建与校验

当前会话 Agent 在已有任务工作区编写、构建和测试应用，Author 负责源码与产物的导入、导出和提交。Author 不增加编译器、Agent 执行器或另一条队列。

应用自己的 `activated` 处理器调用 `web.component-set`，再把返回的 `type` 原样用于 `web.page-set`。例如应用 `local-player` 登记 `Player` 后，完整类型为 `local-player:Player`；`app:Player` 只是占位写法。返回结果继续保留原来的 `name` 与 `revision`。

提交前应执行应用实际的激活处理器，并经真实 Web 组件、页面校验器完成登记。仅测试一个模拟 DOM 中的播放器函数，无法证明激活登记和页面加载可用。测试支持不授予生产环境应用身份、激活或安装权限。可从匹配目标 Web 版本的 Chrona 源码生成单文件 `registration-test.mjs`，复制到普通应用工作区使用；具体命令和完整用例见 [Web 可执行组件](web-executable-components.md)。仓库外回归测试覆盖错误占位类型、实际返回类型、页面版本绑定和嵌套入口的应用根目录。

依赖检查继续使用冻结锁文件及当前离线策略。缺少锁文件、锁文件不匹配、离线缓存缺失和其他安装失败应分别报告，不放宽冻结安装或自动联网。

## 分开记录执行与交付

Run 的运行状态与应用交付事实分别呈现。超时不等于候选没有产生，也不等于应用已交付成功。

会话只从真实、成功且结构完整的工具结果中保存提交关联：原始 admission/request key、receiptId、候选应用 ID 和版本摘要。不能从助手文字、猜测的应用名、其他会话或不完整结果中推断关联。保存后可在 Run 终止时只读核对原始回执、匹配版本的激活状态和页面入口。未知结果保持未知；核对不重新提交、不创建 Run，也不把超时改为成功。

页面入口必须属于记录的实际应用及精确版本。普通声明式页面与可执行组件页面均保存真实登记调用方的版本摘要，并校验它与当前启用版本一致；旧记录或无版本的登记调用保持未知。审批通过、版本激活、页面登记、浏览器行为验证是不同事实。功能验证仍须独立执行；例如音频应实际选择文件、观察播放进度、暂停并验证卸载清理。没有浏览器工具时，应明确标记未验证。

Agent 当前将工具结果的转录文本裁剪为最多 2,000 字符。完整结果才可建立提交关联；裁剪后的回执保持未知，不从残片恢复或猜测。

Agent 应在期限到达前交接已取得的回执、版本、检查报告、入口和未验证事项，避免把剩余时间全部用于轮询。

## 诊断

健康状态中的 incident.reason 必须满足现有 300 字符限制，包括截断标记。摘要被截断时设置现有 truncated 字段；详细诊断保留完整的脱敏证据。过长错误不能让随后正常的发现、健康检查或组件调用再次失败。
