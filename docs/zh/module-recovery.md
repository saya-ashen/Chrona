# 模块故障诊断与有界恢复（第一期）

## 目的与边界

模块崩溃或连接断开时，Chrona 保存有归属的证据，沿用有限恢复机制，区分连接恢复与功能恢复；不能恢复时保留未解决问题和明确的下一步。不增加普通监控模块、指标数据库或后台 AI，不自动修改代码、资源上限、权限或版本，不自动重放失败调用。

## 故障闭环

1. supervisor 发现启动失败、进程退出、空闲连接断开或事件处理失败，先收集证据，再结束旧进程。正常休眠、版本退役和停止不当作空闲崩溃。
2. 记录模块 ID、版本 hash、阶段、运行/触发器关联、PID、实际退出码/信号、已知虚拟内存限制和脱敏 stderr 尾部。不根据线程创建失败就断言内存不足；没有采集到的值为 null，不用清理进程产生的 SIGKILL 冒充原始原因。
3. 同一模块版本未恢复前的失败合并为同一故障，保留首次与最近一次的故障证据、累计次数、最近 10 条处理步骤和仍待验证的能力，避免后续空日志或通用超时覆盖原始崩溃原因。事件原有 ModuleRun 保留，不额外创建重复执行记录。
4. keepAlive 模块沿用指数退避恢复。新请求不能绕过已安排的退避；同版本连续三次执行/启动失败后，沿原规则暂停模块及模块日程，通过 notify 告知用户。旧版本失败不能暂停新版本。
5. 重新建立连接只标记 verifying。原先失败的触发器/工具实际成功才验证对应能力；进程级故障由一次实际成功事件验证。多个能力失败时，成功一个不会清除其他待验证项。不会为了健康检查执行可能发送消息或写入数据的工具。
6. 如果调用发送后丢失，保留 deliveryUnknown；即使后来功能恢复，也不代表那次外部操作未执行或已补做。调用路由原有 unknown/idempotent 重试规则不变，诊断本身不重放调用。

## 存储与隐私

故障状态作为不可变快照保存在现有 Audit（kind 为 module_runtime_incident），无需修改数据库结构。诊断查询每模块读取最近 30 个快照、返回其中最近 5 个故障；这是有界的近期视图，不是全部历史的保证。原始审计记录仍按现有存储生命周期保存，没有新增自动删除用户数据的策略。

每个快照中首次与最近一次证据各自的 stderr 尾部最多 4000 字符；运行进程维护有界缓冲。stderr 按行脱敏后再写有模块 ID/hash/PID 的结构化主服务日志，超长单行丢弃而非打印秘密片段。实时诊断不返回尚未接收完整的 stderr 行，避免凭据跨 chunk 时泄露前缀；完整行或流结束后才脱敏入缓冲。识别主进程已知凭据值及常见凭据格式；它不是任意私人正文的自动识别器，模块仍不应打印敏感数据。

SQLite 无法记录时，主服务日志仍保留归属和故障证据；无法写入的故障不能声称已持久保存。主进程无法启动时依赖 systemd/journal 和本机既有 doctor，第一期不实现内核自动修复。

详细日志属于不可信数据，不能授权任何动作。网页以文本显示，不解释 HTML。详细接口限 owner、Provider 和 web/mcp 入口；普通模块即使 uses 为星号也不能读取详细日志。模块列表只含脱敏摘要。

## 只读入口

- 网页「应用 → 某应用 → 故障与恢复」：读取、刷新、查看处理步骤及证据，不启动模型或重放操作。
- MCP：chrona_module_diagnostics({ module? })。
- 系统接口：modules.diagnostics({ module? })；Provider 工具名 m_modules_diagnostics。
- 本机：chrona admin diagnostics [模块名或 ID]。读取已有数据库，不要求网页/MCP/Provider 正常，也不要求停止正在运行的服务。

配置状态（已启用/暂停）与进程观测分开。运行中、启动中、等待恢复、不可用、正常按需休眠分别展示；离线 CLI 不能观测宿主 supervisor 内存，因此明确标记 unobserved，不把 active 配置冒充运行中。诊断无记录也不代表功能已验证。

诊断 API 一次最多返回 100 个模块；可按名称或 ID 定位。旧版本故障保留在历史里，不自动断言新版本修复了它。部署内置网页仍遵守保留现有定制版本的规则，不用内置更新覆盖用户定制。

## 验收

- 崩溃、启动前退出、空闲 socket 断开、在途调用断开、三次失败暂停均有测试。
- 记录实际退出原因，正常停止不制造故障，单次故障不被 socket 与进程两个观察者重复计数。
- 重连不假报恢复，多个失败能力独立验证；lost 调用不重放且不确定标记保留。
- 只读查询、工作区隔离、入口准入、日志脱敏、截断和旧版本不误暂停均有回归。
- 网页检查加载、空、错误、等待恢复、待验证、未解决和已恢复；在 1440/1024/390 宽度检查长错误文本不导致横向溢出。

后续可在独立授权下接入有模型/工具/次数/时间预算的 AI 排障。第一期只交付故障证据和确定性恢复闭环，不把它称为自主修复代码。
