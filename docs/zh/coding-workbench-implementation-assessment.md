# 编码工作台实现评估

日期：2026-11-08。状态：实现前评估，用户已确认下述范围；本文未交付这些运行时能力。界面方向见[交互原型](../prototypes/coding-workbench/index.html)，参考研究见[项目调研](workbench-reference-research.md)，总体顺序见[开发路线](development-roadmap.md)。

## 已确认的首版范围

- 用户认可原型的轻量布局；产品首先是普通 coding agent 的操作入口。
- 直接修改选定的外部项目，不限于 Chrona 源码。查看 diff、接受成果均不是文件写入的前置条件。
- 工作完成一轮后仍能在同一业务会话继续修改，不要求用户重新创建任务和重复上下文。
- 首版操作 Chrona 所在机器的目录；浏览器可以在其他设备访问，但不是操作浏览器所在设备的文件。
- 从页面添加已有目录，保存后即可选择；不用维护配置文件或重启服务。不要求首版通过 Git URL 克隆。
- 必须支持普通 Git 仓库、已有未提交改动、尚无首次提交的仓库、非 Git 目录及已有空目录。不为满足执行条件自动 git init、提交、reset、clean 或 stash。

## 代码核对与主要缺口

| 部分 | 已有基础 | 需要补充 | 难度判断 |
| --- | --- | --- | --- |
| 直接修改目录 | existing 工作目录和 Pi 文件/命令执行；成果接受只保存业务记录 | 让普通编码成为默认流程，移除强制验收的界面暗示 | 低至中 |
| 连续编码 | Session/Provider 会话标识及日志；coding 有业务会话集合 | 跨轮启动、上下文恢复、历史组织、结果按轮保存和目录重新占用；不能重用旧 Run 能力 | 高 |
| 页面添加项目 | 静态 execution-projects.json 解析、项目授权与位置解析 | owner 页面操作、目录核对、持久项目登记与即时生效；运行中映射不可被无声替换 | 中至高 |
| 任意目录 | 契约已有 commit/snapshot 和无法捕获差异状态；v1 可配置 snapshot 引用 | 将启动与 commit 校验解耦，统一 server 路径；不把不透明 snapshot 字符串当成真实备份 | 中至高 |
| 交流与历史 | 事件、快照、问题和最终回复接口 | 游标接续、去重、缺口提示、流式文字、稳定滚动及刷新后的恢复 | 中至高 |
| 原型样式 | 共享 json-render 组件、输入绑定和数据轮询 | 通用工作区布局、列表、消息呈现与差异展示；不能直接把独立 HTML 变成产品私有旁路 | 中 |
| 控制与恢复 | 调用身份、去重、预算、目录占用、取消与实际停止证据 | 在连续多轮与新增目录上保持相同语义，跨入口状态一致 | 中至高 |

上述等级是工程判断，不是工期承诺。整体中等偏高，主要不是画页面，而是把已有单次执行变成可靠的日常连续编码产品。

核对源码：

- `external/coding/results.ts`：`acceptCodingResult` 只标记接受，不应用补丁。
- `external/coding/sessions.ts`：目前是 workIds 的业务集合，不是完整的多轮 Agent 对话控制器。
- `execution.ts`：start 每次创建新的运行 Session；assertLiveControl 拒绝已结束的运行。因此仅开放输入框不能实现完成后继续。
- `runs.ts`、`integrations/src/steward/pi-launch.ts`：已有 Provider 会话标识保存与恢复入口；能复用底层机制，但 coding 跨轮衔接仍需实现和验证。
- `apps/server/src/config/execution-projects.ts`：目前从配置文件加载项目，页面登记和热生效尚未完成。
- `integrations/src/executor/workspaces.ts`：本地工作区准备路径要求 commit 基线。注意这是对该路径的限制，不能推断整个 v1 都绝对不能启动 snapshot 项目。
- `contracts/src/steward/execution.ts`、`execution-result.ts`：已有 snapshot 引用和差异不可用状态，但不等于已实现任意目录的完整产品流程或可还原快照。
- `builtin/web/src/pages.tsx`：共享渲染基础存在，但现有 Markdown 子集、链接式 TabNav 和轮询本身不能保证原型中的交流体验。

## 建议采用的实现规则

### 会话与执行分开

用户看到持续的项目会话，每次提交目标或继续修改形成一轮执行。Agent 恢复原有 Provider 上下文时继续通过 Agent 服务办理，coding 和页面不直接读取 Pi 的内部文件。每轮使用新的执行授权、预算与去重记录，结果保留历史；不让一个 Run 永久存活。

执行中输入沿用当前工作补充机制；空闲时输入创建下一轮。完成或确认停止后可继续。停止尚未确认时不能启动下一轮，避免两个进程同时写目录。服务重启可以恢复聊天与业务记录，但不得把未知执行自动重新运行。Provider 上下文不可恢复或需要压缩时应明确告知，不能悄悄当成全新上下文。

同一物理目录默认一个写入执行；多个会话需要排队或明确冲突反馈。保留不同项目间既有并行能力。对路径别名、嵌套目录及重叠写入范围进行核对，不能仅比较用户输入的路径字符串。

### 项目登记不绑定永久 commit

登记绑定目录及授权身份，执行前重新核对实际目录与本轮环境。用户在外部切换分支或提交是正常用法，不应因为登记时的旧 commit 永久阻止执行；变化需要按新一轮建立明确基线。运行中不悄悄改变目录映射。

目录新增/失效/移除由 owner 的明确操作管理。移除项目登记不删除项目文件。项目接入使用应用/系统公开调用，既有治理校验留在对应边界，不从 coding 私改服务器配置文件。

### 编码不依赖完整差异

Git 项目可提供可选差异；已有未提交内容不能被声称全由本轮 Agent 创作。非 Git、空目录与无提交仓库仍能读写、运行命令、反馈结果；缺少可靠比较基线时明确说明，不能显示“没有改动”或阻止工作。

首版不强制建设全目录版本控制或备份系统。若输出文件清单，区分执行工具实际记录与 Agent 文本自述；未观测的 shell 写入、超限或省略内容不能伪称完整。可还原快照、自动撤销与逐行审批不作为普通编码的隐含前提。

### 页面使用自然的完成与继续

默认动作是发送目标、补充、答复、停止和继续修改；成果面板用于查看说明、检查与可选差异。普通编码不显示必须点击的“接受成果”。不把自动 commit、push、merge、部署或清理目录绑到完成。遵循用户指令和项目规则执行所需命令；模型及预算沿用服务默认并提供适当配置，不建设新的多执行器管理平台。

## 建议交付顺序与验证

1. **先验证两个后端关键路径。** 用临时 Git/非 Git/空目录及无提交仓库完成一次读写；在同一业务会话完成两轮，核对上下文保留、每轮执行身份、目录占用和重复请求不会重复启动。必要的 Agent/系统契约最小扩展在这里先确定。
2. **完成目录登记与连续会话。** 页面新增、列表与选择即时生效；刷新和服务重启后保留会话；旧静态配置的读取与迁移策略明确，避免两份授权来源互相覆盖。
3. **实现原型中的实际界面。** 复用共享渲染，补列表、交流、原生问答、历史接续和可选成果；完成后输入继续可用。响应式布局与状态反馈并行验收。
4. **集中验证边界。** 双击发送、多标签页、同目录竞争、停止与启动竞争、未知执行、轮次间目录内容变化、事件缺口、部分差异、既有未提交文件保留。

以 fake Provider 和隔离目录做自动检查；真实模型/实际实例验证按明确范围办理。验收必须覆盖“做完后继续改”与“非 Git 目录也能完成工作”，不能以原型截图或单次成功替代。

不要求先完成通用 Run/Call/Artifact 路线；不为本页新增第二执行队列、绕过 caller 或弱化停止证据。个人设备执行、完整终端/编辑器、克隆仓库和复杂工作图界面继续后置。
